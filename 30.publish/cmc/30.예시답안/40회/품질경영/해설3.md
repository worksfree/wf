# 제40회 경영지도사 품질경영 - 문제 3

## 품질관리 용어 설명

---

## 📋 (1) 계통도법 (Systematic Diagram / Tree Diagram) (3점)

### 정의
```
목적이나 목표를 달성하기 위한 수단과 방법을 체계적으로 전개하여
나무 가지 모양으로 표현하는 기법
```

### 특징

**목적**
```
✓ 복잡한 문제를 체계적으로 분해
✓ 목표 달성의 구체적 수단 명확화
✓ 문제 해결의 로드맵 제시
```

**구조**
```
목표/목적 → 1차 수단 → 2차 수단 → 3차 수단 → ...
(WHY?)      (HOW?)     (HOW?)     (HOW?)
```

### 작성 방법

**1단계: 목표 설정**
```
- 달성하고자 하는 최종 목표를 명확히 설정
- 우측에 기록
```

**2단계: 1차 수단 전개**
```
- "어떻게(How) 목표를 달성할 것인가?" 질문
- 주요 수단을 좌측으로 전개
```

**3단계: 2차, 3차 수단 전개**
```
- 각 수단에 대해 다시 "어떻게?" 질문
- 더 구체적인 수단으로 전개
- 실행 가능한 수준까지 세분화
```

**4단계: 검토 및 수정**
```
- 누락된 수단 확인
- 논리적 연결성 점검
- 실행 가능성 검토
```

### 도표 형식

```
                                  ┌─ 2차 수단 1-1
                    ┌─ 1차 수단 1 ┼─ 2차 수단 1-2
                    │             └─ 2차 수단 1-3
                    │
                    │             ┌─ 2차 수단 2-1
목표/목적 ──────────┼─ 1차 수단 2 ┼─ 2차 수단 2-2
                    │             └─ 2차 수단 2-3
                    │
                    │             ┌─ 2차 수단 3-1
                    └─ 1차 수단 3 ┼─ 2차 수단 3-2
                                  └─ 2차 수단 3-3
```

### 실무 예시

**목표: 불량률 50% 감소**
```
불량률 50% 감소 ─┬─ 작업자 기능 향상 ─┬─ 교육 프로그램 실시
                │                   ├─ 숙련도 평가 제도
                │                   └─ 작업 표준서 개정
                │
                ├─ 설비 개선 ───────┬─ 정밀도 향상
                │                   ├─ 예방 보전 강화
                │                   └─ 노후 설비 교체
                │
                └─ 재료 품질 향상 ──┬─ 공급업체 평가 강화
                                    ├─ 수입검사 엄격화
                                    └─ 협력업체 기술지원
```

### 활용 분야
```
✓ 신제품 개발 계획
✓ 품질개선 활동
✓ 원가절감 프로젝트
✓ 업무 프로세스 개선
```

### 장점
```
- 목표와 수단의 체계적 연결
- 문제 해결 방향 명확화
- 팀원 간 공감대 형성
- 실행 계획 수립 용이
```

## 📊 (2) 매트릭스도 (Matrix Diagram) (3점)

### 정의
```
두 개 이상의 요소 간 관계를 행과 열의 매트릭스(격자) 형태로 표현하여
문제의 소재와 형태를 명확히 하는 기법
```

### 목적
```
✓ 복잡한 요소 간 상관관계 파악
✓ 문제 요인의 규명
✓ 우선순위 결정
✓ 다차원적 분석
```

### 기본 구조

```
           요소 B₁  요소 B₂  요소 B₃  요소 B₄
요소 A₁      ○       △       ◎
요소 A₂      △               ○       ◎
요소 A₃              ◎       △       ○
요소 A₄      ◎       ○               △

기호 의미:
◎ : 강한 관계 (9점)
○ : 중간 관계 (3점)
△ : 약한 관계 (1점)
공백: 관계 없음 (0점)
```

### 매트릭스 유형

**1. L형 매트릭스 (2차원)**
```
- 가장 기본적인 형태
- 행과 열 2개 요소의 관계
```

**2. T형 매트릭스 (3차원)**
```
- 3개 요소 간 관계
- A-B, B-C 관계 동시 분석
```

**3. Y형 매트릭스 (3차원)**
```
- 3개 요소를 Y자 형태로 배치
- 순환적 관계 분석
```

**4. X형 매트릭스 (4차원)**
```
- 4개 요소 간 관계
- A-B, C-D, A-C, B-D 관계
```

**5. C형 매트릭스 (입체형)**
```
- 3차원 입체 매트릭스
- 매우 복잡한 관계 분석
```

### 작성 방법

**1단계: 비교 요소 선정**
```
- 행(Row)에 배치할 요소 결정
- 열(Column)에 배치할 요소 결정
```

**2단계: 매트릭스 작성**
```
- 표 형태로 골격 그리기
- 각 요소를 행과 열에 배치
```

**3단계: 관계 표시**
```
- 각 교차점에서 관계의 강도 표시
- 기호(◎, ○, △) 또는 점수 사용
```

**4단계: 분석 및 해석**
```
- 관계가 강한 부분 파악
- 중요 요인 도출
- 우선순위 결정
```

### 실무 예시: QFD (품질기능전개)의 품질의 집 (House of Quality)

```
               |  고객요구사항 1 | 고객요구사항 2 | 고객요구사항 3
───────────────┼────────────────┼────────────────┼────────────────
기술특성 1      |       ◎        |       △        |       ○
───────────────┼────────────────┼────────────────┼────────────────
기술특성 2      |       ○        |       ◎        |       △
───────────────┼────────────────┼────────────────┼────────────────
기술특성 3      |       △        |       ○        |       ◎
───────────────┼────────────────┼────────────────┼────────────────
중요도 (점수)   |       45       |       38       |       52
```

### 실무 예시: 불량 유형과 공정의 관계

```
           공정A  공정B  공정C  공정D  발생빈도
불량 유형1   ◎     △            ○      15
불량 유형2         ◎     ○      △      23
불량 유형3   ○     △     ◎      ○      18
불량 유형4   △           △      ◎      12

→ 분석: 공정B와 공정C가 가장 많은 불량 원인
```

### 활용 분야
```
✓ QFD (고객요구 - 설계특성 연계)
✓ FMEA (고장모드 - 영향 분석)
✓ 업무 분장 (담당자 - 업무 매칭)
✓ 기능 배치 (부서 - 기능 매칭)
```

### 장점
```
- 복잡한 관계의 시각화
- 다차원 분석 가능
- 의사소통 도구
- 우선순위 결정 용이
```

## 🎯 (3) DMAIC (4점)

### 정의
```
DMAIC: 6시그마 프로젝트의 문제 해결 프로세스
- Define (정의)
- Measure (측정)
- Analyze (분석)
- Improve (개선)
- Control (관리)
```

### 개요
```
- 6시그마의 핵심 방법론
- 데이터 기반 의사결정
- 구조화된 문제 해결 프로세스
- MAIC의 앞에 D(Define)를 추가하여 발전
```

---

### 1단계: 정의 (Define)

#### 목적
```
프로젝트의 목표와 범위를 명확히 정의
```

#### 주요 활동
```
✓ 고객 요구사항(CTQ) 파악
✓ 프로젝트 목표 설정
✓ 프로젝트 범위 결정 (Scope)
✓ 프로젝트 팀 구성
✓ 일정 및 자원 계획
```

#### 주요 산출물
```
- 프로젝트 헌장 (Project Charter)
- SIPOC 다이어그램
- VOC (Voice of Customer)
- CTQ Tree
```

#### 핵심 질문
```
"무엇이 문제인가?"
"고객은 무엇을 원하는가?"
"프로젝트의 목표는 무엇인가?"
```

---

### 2단계: 측정 (Measure)

#### 목적
```
현재 프로세스의 성능을 데이터로 측정하고 평가
```

#### 주요 활동
```
✓ 측정 지표 선정 (KPI)
✓ 데이터 수집 계획 수립
✓ 측정 시스템 분석 (MSA)
✓ 현재 성능 수준 파악 (Baseline)
✓ 공정 능력 분석 (Process Capability)
```

#### 주요 산출물
```
- 데이터 수집 계획서
- MSA (Measurement System Analysis) 결과
- 현재 시그마 수준
- 공정 능력 지수 (Cp, Cpk)
- 히스토그램, 관리도
```

#### 핵심 지표
```
- DPMO (Defects Per Million Opportunities)
- 시그마 수준 (Sigma Level)
- 수율 (Yield)
```

#### 핵심 질문
```
"현재 상태는 어떠한가?"
"얼마나 나쁜가?"
"측정 시스템은 신뢰할 수 있는가?"
```

---

### 3단계: 분석 (Analyze)

#### 목적
```
문제의 근본 원인(Root Cause)을 데이터 기반으로 규명
```

#### 주요 활동
```
✓ 프로세스 맵 작성
✓ 잠재 원인 도출 (Brainstorming)
✓ 특성 요인도 작성
✓ 통계 분석 (가설 검정, 회귀 분석)
✓ 핵심 원인 규명 (Vital Few)
```

#### 주요 기법
```
- 특성 요인도 (Fishbone Diagram)
- 파레토 차트
- 가설 검정 (t-test, ANOVA)
- 상관 분석, 회귀 분석
- 다변량 분석
```

#### 주요 산출물
```
- 프로세스 맵
- 특성 요인도
- 통계 분석 결과
- 검증된 근본 원인
```

#### 핵심 질문
```
"왜 문제가 발생하는가?"
"핵심 원인은 무엇인가?"
"데이터가 원인을 뒷받침하는가?"
```

---

### 4단계: 개선 (Improve)

#### 목적
```
근본 원인을 제거하고 프로세스를 개선
```

#### 주요 활동
```
✓ 개선 아이디어 도출
✓ 개선안 평가 및 선택
✓ 파일럿 테스트 (Pilot Test)
✓ 개선안 실행
✓ 개선 효과 검증
```

#### 주요 기법
```
- 실험 계획법 (DOE: Design of Experiments)
- Poka-Yoke (실수 방지)
- 시뮬레이션
- 비용-편익 분석
```

#### 주요 산출물
```
- 개선 실행 계획
- 파일럿 테스트 결과
- 개선 전후 비교 데이터
- 표준 작업 절차서 (SOP)
```

#### 핵심 질문
```
"어떻게 개선할 것인가?"
"개선 효과가 입증되었는가?"
"실행 가능한가?"
```

---

### 5단계: 관리 (Control)

#### 목적
```
개선된 프로세스를 유지하고 지속적으로 관리
```

#### 주요 활동
```
✓ 관리 계획 수립
✓ 표준화 및 문서화
✓ 통계적 공정관리 (SPC) 적용
✓ 교육 및 훈련
✓ 프로젝트 종료 및 이관
```

#### 주요 기법
```
- 관리도 (Control Chart)
- SPC (Statistical Process Control)
- 표준 작업 절차 (SOP)
- 체크리스트
```

#### 주요 산출물
```
- 관리 계획서
- 관리도
- 표준 작업 절차서
- 교육 자료
- 프로젝트 종료 보고서
```

#### 핵심 질문
```
"개선 효과를 어떻게 유지할 것인가?"
"재발 방지 대책은?"
"담당자는 누구인가?"
```

---

### DMAIC 프로세스 흐름도

```
┌──────────────────┐
│   Define (정의)   │  ← 무엇이 문제인가?
│  프로젝트 선정    │
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│   Measure (측정)  │  ← 현재 상태는?
│  데이터 수집      │
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  Analyze (분석)   │  ← 왜 문제가 발생?
│  근본 원인 규명   │
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  Improve (개선)   │  ← 어떻게 개선?
│  개선안 실행      │
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│  Control (관리)   │  ← 어떻게 유지?
│  표준화, 관리     │
└──────────────────┘
```

---

### DMAIC의 특징

**데이터 기반 의사결정**
```
- 추측이 아닌 데이터로 판단
- 통계적 분석 활용
- 객관적 증거 확보
```

**체계적 문제 해결**
```
- 5단계 구조화된 프로세스
- 각 단계별 명확한 목표
- Gate Review (단계별 검증)
```

**재발 방지**
```
- 근본 원인 제거
- 표준화 및 관리 체계
- 지속적 모니터링
```

---

### DMAIC vs PDCA

| 구분 | DMAIC | PDCA |
|------|-------|------|
| **단계** | 5단계 | 4단계 |
| **복잡도** | 높음 | 낮음 |
| **데이터 의존도** | 매우 높음 | 중간 |
| **적용 범위** | 복잡한 문제 | 일상적 개선 |
| **기간** | 3~6개월 | 짧은 주기 |
| **방법론** | 6시그마 | TQM |

---

### 활용 분야
```
✓ 제조업 불량률 감소
✓ 서비스 프로세스 개선
✓ 리드타임 단축
✓ 원가 절감
✓ 고객 만족도 향상
```

## 📝 최종 요약

### 계통도법
```
목표 달성 수단을 나무 가지 형태로 체계적 전개
→ 문제 해결의 로드맵
```

### 매트릭스도
```
요소 간 관계를 행렬 형태로 표현
→ 복잡한 관계의 시각화 및 우선순위 결정
```

### DMAIC
```
6시그마 문제 해결 5단계
Define → Measure → Analyze → Improve → Control
→ 데이터 기반 체계적 품질개선
```

```
✓ 실무 적용 방법 제시
✓ 도표나 예시로 이해도 증명
✓ 핵심 키워드 강조
```
