# 제40회 경영지도사 품질경영 - 문제 6

## 신뢰성 관리

---

## 📋 (1) 고장나무 분석 (FTA: Fault Tree Analysis) (5점)

### 정의
```
FTA (Fault Tree Analysis):
시스템의 바람직하지 않은 사건(고장)을 최상위에 놓고,
그 원인을 논리 기호를 사용하여 나무(Tree) 형태로
연역적(Top-Down)으로 분석하는 기법
```

---

### 목적

```
✓ 시스템 고장의 원인 규명
✓ 고장 발생 확률 계산
✓ 취약점 파악 및 개선
✓ 안전성 평가
✓ 설계 단계에서의 신뢰성 확보
```

---

### 특징

**1. 연역적 분석 (Deductive Analysis)**
```
Top-Down 방식:
최상위 고장 사건 → 중간 사건 → 기본 사건

정해진 고장부터 원인을 찾아 내려감
```

**2. 논리 기호 사용**
```
AND 게이트, OR 게이트 등 논리 게이트로 인과관계 표현
```

**3. 정량적 분석 가능**
```
각 사건의 확률을 이용하여 최상위 사건의 발생 확률 계산
```

**4. 시각적 표현**
```
복잡한 인과관계를 나무 구조로 명확히 표현
```

---

### 주요 용어

#### 사건 (Event)

**① 최상위 사건 (Top Event)**
```
- 분석 대상이 되는 바람직하지 않은 사건
- FT 다이어그램의 최상단
- 예: 시스템 고장, 사고 발생
```

**② 중간 사건 (Intermediate Event)**
```
- 최상위 사건과 기본 사건 사이의 사건
- 논리 게이트의 출력
```

**③ 기본 사건 (Basic Event)**
```
- 더 이상 분해할 수 없는 최하위 사건
- FT의 말단 사건
- 고장률, 고장 확률이 알려진 사건
```

**④ 미전개 사건 (Undeveloped Event)**
```
- 더 분해 가능하나 정보 부족 등으로 전개하지 않은 사건
```

---

### 논리 게이트 (Logic Gate)

#### AND 게이트 (∩)
```
기호: ∩ 또는 ⌒

의미: 모든 입력 사건이 동시에 발생해야 출력 사건 발생

        출력
         │
      ┌──∩──┐
      │     │
    입력1  입력2

예: 두 개의 안전장치가 모두 고장나야 사고 발생
P(출력) = P(입력1) × P(입력2)
```

#### OR 게이트 (∪)
```
기호: ∪ 또는 ⌣

의미: 입력 사건 중 하나만 발생해도 출력 사건 발생

        출력
         │
      ┌──∪──┐
      │     │
    입력1  입력2

예: 두 개의 부품 중 하나만 고장나도 시스템 고장
P(출력) = 1 - (1-P(입력1)) × (1-P(입력2))
        ≈ P(입력1) + P(입력2)  (확률이 작을 때)
```

#### 기타 게이트
```
- 배타적 OR 게이트 (XOR): 하나만 발생
- 우선 AND 게이트: 특정 순서로 발생
- 금지 게이트 (Inhibit): 조건부 발생
```

---

### 사건 기호

```
┌─────┐
│     │  기본 사건 (Basic Event)
└──┬──┘  - 원으로 표시
   │     - 더 이상 분해 안 함

   ◇     미전개 사건 (Undeveloped Event)
   │     - 마름모로 표시
   │     - 정보 부족으로 미전개

┌─────┐
│     │  중간 사건 (Intermediate Event)
└──┬──┘  - 사각형으로 표시
   │     - 게이트의 출력
```

---

### FTA 작성 절차

**1단계: 최상위 사건 정의**
```
- 분석 대상이 되는 바람직하지 않은 사건 명확히 정의
- 예: "자동차 브레이크 고장"
```

**2단계: 시스템 경계 설정**
```
- 분석 범위 결정
- 시스템 구조 및 기능 파악
```

**3단계: 고장나무 전개**
```
- 최상위 사건의 직접 원인 찾기
- 논리 게이트(AND/OR)로 연결
- 기본 사건까지 반복 전개
```

**4단계: 정성적 분석**
```
- 최소 컷 셋(Minimal Cut Set) 도출
- 취약 경로 파악
```

**5단계: 정량적 분석**
```
- 각 기본 사건의 확률 할당
- 최상위 사건의 발생 확률 계산
```

**6단계: 개선 대책 수립**
```
- 고위험 경로 개선
- 중복성(Redundancy) 추가
- 예방 보전 강화
```

---

### FTA 예시

```
                    ┌──────────────┐
                    │ 자동차 사고   │  최상위 사건
                    │  발생        │
                    └──────┬───────┘
                           │
                      ┌────∪────┐     OR 게이트
                      │         │
          ┌───────────┴─┐   ┌───┴──────────┐
          │브레이크 고장 │   │ 조향장치 고장│  중간 사건
          └──────┬───────┘   └───┬──────────┘
                 │               │
            ┌────∩────┐     ┌────∩────┐     AND 게이트
            │         │     │         │
        ┌───┴───┐ ┌───┴───┐ ┌───┴───┐ ┌───┴───┐
        │브레이크│ │유압계통│ │핸들   │ │조향축 │  기본 사건
        │패드마모│ │누유   │ │파손   │ │파손   │
        └───○───┘ └───○───┘ └───○───┘ └───○───┘
```

---

### 최소 컷 셋 (Minimal Cut Set)

#### 정의
```
최상위 사건을 발생시키는 기본 사건의 최소 조합
```

#### 의미
```
- 컷 셋: 최상위 사건을 발생시키는 기본 사건 집합
- 최소 컷 셋: 더 이상 줄일 수 없는 최소 조합
- 시스템의 취약 경로
```

#### 예시
```
위 FTA에서 최소 컷 셋:
1. {브레이크 패드 마모, 유압계통 누유}
2. {핸들 파손, 조향축 파손}

→ 이 조합들이 발생하면 사고 발생
→ 우선 개선 대상
```

---

### 정량적 분석 예시

```
가정:
P(브레이크 패드 마모) = 0.01
P(유압계통 누유) = 0.02
P(핸들 파손) = 0.005
P(조향축 파손) = 0.008

계산:
P(브레이크 고장) = 0.01 × 0.02 = 0.0002  (AND)
P(조향장치 고장) = 0.005 × 0.008 = 0.00004  (AND)
P(자동차 사고) ≈ 0.0002 + 0.00004 = 0.00024  (OR)
             = 0.024% = 240 ppm
```

## 🔍 (2) 고장증상과 영향분석 (FMEA: Failure Mode and Effect Analysis) (5점)

### 정의
```
FMEA (Failure Mode and Effect Analysis):
시스템, 제품, 공정에서 발생 가능한 고장 모드(Failure Mode)를
사전에 파악하고, 그 영향을 분석하여 우선순위를 정하고
예방 조치를 취하는 귀납적(Bottom-Up) 분석 기법
```

---

### 목적

```
✓ 잠재적 고장 사전 파악
✓ 고장의 영향 평가
✓ 고장 예방 조치 수립
✓ 설계 및 공정 개선
✓ 고객 만족도 향상
✓ 보증 비용 절감
```

---

### 특징

**1. 귀납적 분석 (Inductive Analysis)**
```
Bottom-Up 방식:
개별 부품/공정 → 시스템 전체 영향

작은 고장부터 시작하여 전체 영향 추적
```

**2. 사전 예방적**
```
- 설계/개발 단계에서 수행
- 문제 발생 전 예방
- "실패로부터 학습"
```

**3. 체계적 문서화**
```
- FMEA 양식에 체계적 기록
- 지식 축적 및 공유
```

**4. 정량적 평가**
```
- RPN (Risk Priority Number) 계산
- 우선순위 결정
```

---

### FMEA 유형

#### 1. 설계 FMEA (Design FMEA, DFMEA)
```
대상: 제품 설계
시기: 설계 단계
목적: 설계 결함 사전 발견
담당: 설계 부서
```

#### 2. 공정 FMEA (Process FMEA, PFMEA)
```
대상: 제조 공정
시기: 공정 설계 단계
목적: 공정 문제 사전 발견
담당: 제조 부서
```

#### 3. 시스템 FMEA (System FMEA)
```
대상: 전체 시스템
범위: 시스템 수준
목적: 시스템 간 상호작용 분석
```

---

### FMEA 주요 개념

#### 고장 모드 (Failure Mode)
```
정의: 부품, 서브시스템, 시스템이 기능을 수행하지 못하는 방식

예시:
- 파손, 변형, 균열
- 단선, 단락, 누전
- 마모, 부식
- 작동 불량, 기능 정지
```

#### 고장 영향 (Effect of Failure)
```
정의: 고장 모드가 발생했을 때 시스템, 고객, 작업자에게 미치는 결과

예시:
- 시스템 정지
- 성능 저하
- 안전사고
- 고객 불만
```

#### 고장 원인 (Cause of Failure)
```
정의: 고장 모드를 유발하는 설계상, 공정상 결함

예시:
- 재료 불량
- 설계 오류
- 가공 불량
- 조립 실수
```

---

### FMEA 양식 및 평가 항목

#### 표준 FMEA 양식

| 항목 | 고장모드 | 고장영향 | 심각도(S) | 고장원인 | 발생도(O) | 현재관리 | 검출도(D) | RPN | 조치사항 | 책임자 | 완료일 |
|------|----------|----------|-----------|----------|-----------|----------|-----------|-----|----------|--------|--------|
| ... | ... | ... | ... | ... | ... | ... | ... | ... | ... | ... | ... |

---

### 평가 지수

#### 1. 심각도 (Severity, S)

**정의**: 고장이 발생했을 때 영향의 심각한 정도

**평가 척도** (1~10점)

| 점수 | 등급 | 설명 |
|------|------|------|
| 10 | 매우 심각 | 안전 문제, 법규 위반 |
| 9 | 심각 | 시스템 기능 상실 |
| 7~8 | 높음 | 주요 기능 저하 |
| 4~6 | 중간 | 부분 기능 저하 |
| 2~3 | 낮음 | 경미한 불편 |
| 1 | 매우 낮음 | 영향 없음 |

---

#### 2. 발생도 (Occurrence, O)

**정의**: 고장 원인이 발생할 가능성

**평가 척도** (1~10점)

| 점수 | 발생 확률 | 설명 |
|------|-----------|------|
| 10 | ≥ 100 ppm | 거의 확실히 발생 |
| 9 | 50 ppm | 매우 높음 |
| 7~8 | 20 ppm | 높음 |
| 4~6 | 2~10 ppm | 중간 |
| 2~3 | 0.1~1 ppm | 낮음 |
| 1 | < 0.01 ppm | 거의 불가능 |

---

#### 3. 검출도 (Detection, D)

**정의**: 현재의 관리 방법으로 고장을 검출할 수 없는 정도
(높을수록 검출 어려움)

**평가 척도** (1~10점)

| 점수 | 검출 능력 | 설명 |
|------|-----------|------|
| 10 | 불가능 | 검출 수단 없음 |
| 9 | 매우 낮음 | 간헐적 검사 |
| 7~8 | 낮음 | 샘플 검사 |
| 4~6 | 중간 | 통계적 검사 |
| 2~3 | 높음 | 자동 검출 |
| 1 | 매우 높음 | 오류 방지 설계 |

---

### RPN (Risk Priority Number)

#### 정의
```
RPN = S × O × D

위험 우선순위 지수
고장 모드의 위험도를 정량화한 값
```

#### 범위
```
최소: 1 × 1 × 1 = 1
최대: 10 × 10 × 10 = 1,000
```

#### 활용
```
RPN이 높을수록 우선 개선 대상
보통 RPN ≥ 100 이상을 개선 대상으로 선정
```

---

### FMEA 수행 절차

**1단계: 준비**
```
- FMEA 팀 구성 (다기능 팀)
- 분석 대상 선정
- 시스템 구조 파악
```

**2단계: 고장 모드 파악**
```
- 각 항목별 가능한 고장 모드 나열
- 브레인스토밍, 과거 데이터 활용
```

**3단계: 고장 영향 분석**
```
- 각 고장 모드의 영향 기술
- 심각도(S) 평가
```

**4단계: 고장 원인 분석**
```
- 각 고장 모드의 원인 파악
- 발생도(O) 평가
```

**5단계: 현재 관리 방법 확인**
```
- 현재의 예방/검출 수단 파악
- 검출도(D) 평가
```

**6단계: RPN 계산**
```
- RPN = S × O × D 계산
- 우선순위 결정
```

**7단계: 개선 조치 수립**
```
- 고 RPN 항목에 대한 개선 대책
- 담당자 및 완료 기한 설정
```

**8단계: 조치 후 재평가**
```
- 개선 조치 실시 후 S, O, D 재평가
- 새로운 RPN 계산
- 효과 확인
```

**9단계: 문서화 및 지속 관리**
```
- FMEA 결과 문서화
- 정기적 갱신
```

---

### FMEA 예시

**제품**: 자동차 브레이크 시스템
**부품**: 브레이크 패드

| 항목 | 고장모드 | 고장영향 | S | 고장원인 | O | 현재관리 | D | RPN | 조치사항 |
|------|----------|----------|---|----------|---|----------|---|-----|----------|
| 브레이크 패드 | 마모 | 제동력 저하 | 9 | 저품질 재료 | 4 | 정기점검 | 3 | 108 | 재료 규격 강화 |
| 브레이크 패드 | 균열 | 제동 불능 | 10 | 과열 | 3 | 육안 검사 | 5 | 150 | 냉각 시스템 개선 |
| 브레이크 패드 | 이탈 | 제동 불능 | 10 | 잘못된 조립 | 2 | Poka-Yoke | 1 | 20 | 현재 관리 유지 |

**분석 결과**
```
- 균열 (RPN=150): 최우선 개선 대상 → 냉각 시스템 개선
- 마모 (RPN=108): 차순위 개선 → 재료 규격 강화
- 이탈 (RPN=20): 현재 관리 양호 → 유지
```

---

### 개선 전략

#### 심각도(S) 저감
```
- 설계 변경
- 여유도(Margin) 증가
- 중복 설계(Redundancy)
→ 가장 어려움, 근본적 해결
```

#### 발생도(O) 저감
```
- 공정 개선
- 작업 표준화
- 예방 보전
- 재료 품질 향상
→ 가장 효과적
```

#### 검출도(D) 저감 (검출 능력 향상)
```
- 검사 강화
- 자동화 검사
- Poka-Yoke (실수 방지)
- 센서 추가
→ 비교적 용이
```

## 💡 FTA vs FMEA 비교

| 구분 | FTA | FMEA |
|------|-----|------|
| **방향** | 연역적 (Top-Down) | 귀납적 (Bottom-Up) |
| **시작점** | 특정 고장 사건 | 개별 부품/공정 |
| **초점** | 특정 사건의 원인 | 모든 고장 모드 |
| **표현** | 나무 구조 (그래프) | 표 (Table) |
| **정량화** | 확률 계산 | RPN 계산 |
| **장점** | 복잡한 인과관계 명확 | 포괄적, 체계적 |
| **단점** | 특정 사건만 분석 | 복잡한 상호작용 한계 |
| **시기** | 주로 설계 완료 후 | 설계/개발 초기 |
| **활용** | 치명적 고장 분석 | 전반적 개선 |

---

### 상호 보완적 활용

```
FMEA로 잠재 고장 모드 파악
     ↓
치명적 고장 모드 선정
     ↓
FTA로 상세 원인 분석
     ↓
종합 개선 대책 수립
```

## 📝 최종 정리

### (1) FTA
```
- 연역적(Top-Down) 분석
- 논리 게이트(AND/OR)로 나무 구조
- 특정 고장 사건의 원인 규명
- 정량적 확률 계산 가능
- 최소 컷 셋으로 취약 경로 파악
```

### (2) FMEA
```
- 귀납적(Bottom-Up) 분석
- 표 형식으로 체계적 기록
- 모든 고장 모드 포괄 분석
- RPN (S×O×D)으로 우선순위 결정
- 사전 예방 및 지속 개선
```
