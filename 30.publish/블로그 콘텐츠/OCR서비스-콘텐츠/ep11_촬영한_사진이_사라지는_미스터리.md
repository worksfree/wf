# EP11: 촬영한 사진이 사라지는 미스터리 — 범인을 세 번 잘못 짚은 이야기

**시리즈**: OCR 서비스구축 #11
**이 글을 읽고 나면**: 모바일 웹에서 네이티브 카메라 앱으로 전환했다가 돌아올 때 브라우저 탭이 통째로 죽을 수 있다는 것, 그리고 겹쳐 있는 여러 버그를 하나씩 벗겨내며 진짜 원인에 도달하는 디버깅 과정을 알 수 있습니다.

---

## 핵심 한 줄 요약
> 모바일에서 사진을 찍고 앱으로 돌아오면 방금 찍은 사진이 사라지는 문제를, 세 번의 서로 다른 원인을 순서대로 고치고 나서야 완전히 해결했다. 세 번째 원인은 "브라우저 자체가 죽고 다시 살아나는" 근본적인 구조 문제였고, 결국 네이티브 카메라 앱 전환 자체를 없애는 것으로 끝났다.

> **자주 묻는 질문**
> **Q. 처음부터 세 번째 원인을 알 수 없었나요?** → 몰랐다. 증상(사진이 사라짐)만 보면 원인 후보가 여러 개였고, 하나씩 고쳐가며 증상이 얼마나 줄어드는지로 다음 원인을 좁혀나갔다. 처음 두 개도 실제로 존재하는 버그였다 — 세 번째만 있었던 게 아니라 세 개가 겹쳐 있었다.
> **Q. `<input type="file" capture>`가 원래 이런 문제가 있나요?** → 모바일 브라우저·OS·기기 조합에 따라 다르다. 이 프로젝트에서 테스트한 환경(안드로이드)에서는 카메라 앱 전환이 브라우저 탭의 메모리를 회수해버리는 현상이 재현됐다. 근본 원인을 없애는 가장 확실한 방법은 네이티브 앱 전환 자체를 안 하는 것이었다.
> **Q. getUserMedia로 바꾸면 뭐가 좋아지나요?** → 페이지를 벗어나지 않고 그 자리에서 카메라 스트림을 받아 촬영하기 때문에, 애초에 "탭이 백그라운드로 밀려나서 죽는" 상황 자체가 발생하지 않는다.

---

## 문제 상황

모바일 웹에서 "사진 촬영" 버튼을 누르면 `<input type="file" capture="environment">`로 네이티브 카메라 앱을 띄우고, 촬영한 사진을 받아 페이지로 돌아오는 방식으로 구현했다. 사용자 테스트 중 이 흐름이 가끔(항상은 아니고) 실패한다는 리포트가 왔다 — 사진을 찍고 "확인"을 누르면 앱으로 돌아오는데, 파일 선택창이 빈 상태였다.

## 원인 1 — 새로고침 후 홈으로 떨어지는 버그

첫 증상은 "카메라에서 돌아오면 허브가 홈 화면으로 돌아가 있다"는 것이었다. 카메라 앱 전환 → 복귀 과정이 브라우저 입장에서는 페이지 새로고침과 비슷하게 처리될 수 있는데, 이 허브는 새로고침 시 사용자가 보고 있던 화면(이 경우 OCR 서비스 페이지)을 기억하지 못하고 항상 홈으로 돌아가게 되어 있었다.

**수정**: 현재 열려있는 페이지 경로를 `sessionStorage`에 저장해두고, 페이지 로드 시 그 값이 있으면 홈 대신 그 경로로 복원하도록 고쳤다.

```javascript
window.addEventListener("beforeunload", () => {
  sessionStorage.setItem("wf_last_path", currentPath);
});
// 로드 시
const savedPath = sessionStorage.getItem("wf_last_path");
if (savedPath) restorePath(savedPath);
```

이걸로 "홈으로 떨어지는" 증상은 사라졌다. 그런데 카메라로 찍은 사진 자체는 여전히 안 나타났다 — 하나를 고쳤더니 다음 증상이 드러난 것이다.

## 원인 2 — 계정전환 오판으로 복원한 화면이 다시 덮어써짐

경로 복원까지는 되는데, 화면이 잠깐 복원됐다가 다시 홈으로 리셋되는 현상이 남아있었다. 로그를 추적해보니 `onAuthComplete()`(로그인 상태 확인 후 호출되는 함수)가 "계정이 전환됐다"고 잘못 판단하고 있었다.

이 함수는 원래 "사용자가 다른 계정으로 로그인했으면 화면을 초기화한다"는 의도로 짜여 있었는데, **페이지가 새로 로드된 직후의 첫 호출을 "계정 전환"으로 오인**하고 있었다. 이전 세션 정보가 아직 없는 상태(첫 호출)와 실제로 다른 계정으로 바뀐 상태를 구분하지 못했던 것이다.

```javascript
// 수정 전: 첫 호출도 "전환"으로 오판
function onAuthComplete(newUserId) {
  if (newUserId !== lastUserId) { resetToHome(); }  // 첫 호출 시 lastUserId가 없어서 항상 참
  lastUserId = newUserId;
}

// 수정 후: 첫 호출은 전환이 아니라 "최초 진입"으로 구분
function onAuthComplete(newUserId) {
  if (lastUserId !== undefined && newUserId !== lastUserId) { resetToHome(); }
  lastUserId = newUserId;
}
```

이제 방금 복원한 화면이 다시 덮어써지지 않았다. 라우팅 자체는 이걸로 완전히 고쳐졌다. 그런데 사진은 **여전히** 미리보기에 나타나지 않았다.

## 원인 3 — 진짜 범인: 브라우저 탭 자체가 죽어있었다

여기까지 오니 "라우팅 문제가 아니라 사진 데이터 자체가 애초에 안 넘어오고 있다"는 게 명확해졌다. `<input type="file" capture="environment">`의 동작 방식을 다시 살펴봤다.

이 방식은 모바일에서 **네이티브 카메라 앱을 새로 실행**한다 — 브라우저 탭에서 완전히 벗어나는 것이다. 안드로이드 환경에서는 이 전환 과정에서 브라우저(탭)가 메모리 부족 등의 이유로 백그라운드에서 아예 종료되고, 카메라 앱에서 "확인"을 누르면 브라우저가 처음부터 다시 실행되는 경우가 있었다. 이 경우 `<input>` 엘리먼트가 들고 있던 파일 참조 자체가 날아간다 — 페이지가 재시작되면서 그 상태를 아예 잃어버리는 것이다.

원인 1·2에서 고친 "복원 로직"이 실제로는 이 완전 재시작 상황을 감춰주고 있었을 뿐, **탭이 죽고 다시 시작되는 근본적인 문제 자체는 그대로 남아있었다.**

**수정**: `<input capture>` 방식을 완전히 버리고, `getUserMedia()`로 페이지 안에서 카메라 스트림을 직접 받아 촬영하는 모달로 바꿨다.

```javascript
async function openCameraModal() {
  const stream = await navigator.mediaDevices.getUserMedia({
    video: { facingMode: "environment" }
  });
  document.getElementById("cameraVideo").srcObject = stream;
  document.getElementById("cameraModal").style.display = "flex";
}

function captureCameraPhoto() {
  const video = document.getElementById("cameraVideo");
  const canvas = document.createElement("canvas");
  canvas.width = video.videoWidth;
  canvas.height = video.videoHeight;
  canvas.getContext("2d").drawImage(video, 0, 0);
  canvas.toBlob((blob) => handleFile(new File([blob], "capture.jpg", { type: "image/jpeg" })));
}
```

이 방식은 네이티브 앱으로 전혀 나가지 않는다 — 페이지 안의 `<video>` 엘리먼트로 카메라 미리보기를 보여주고, 셔터 버튼을 누르면 그 프레임을 캔버스로 캡처해서 바로 파일로 만든다. 탭이 백그라운드로 밀려날 일 자체가 없으니, 원인 3이 발생할 조건 자체가 사라졌다.

## 왜 세 개가 겹쳐 있었나

돌이켜보면 원인 1·2는 "새로고침이 자주 발생하는 상황을 허브가 잘 처리 못 한다"는, 이 앱 자체의 별개 버그였다. 카메라 문제가 아니었어도 언젠가 다른 계기(예: 모바일 브라우저의 자동 탭 재시작)로 드러났을 문제였다. 원인 3(탭이 죽는 것)이 원인 1·2가 숨어있던 증상을 우연히 자주 트리거하는 방아쇠 역할을 한 것이다.

**"증상 하나에 원인 하나"라고 가정하고 첫 번째 원인을 고친 뒤 증상이 줄어들면 거기서 멈추기 쉬운데, 실제로는 여러 개가 겹쳐 있을 수 있다.** 원인 1을 고치고 나서 증상이 부분적으로 남아있었기 때문에 계속 파고들 수 있었다 — 만약 원인 1만 고치고 "이제 됐겠지"라고 넘어갔다면, 원인 2·3은 훨씬 나중에, 더 파악하기 어려운 형태로 다시 나타났을 것이다.
