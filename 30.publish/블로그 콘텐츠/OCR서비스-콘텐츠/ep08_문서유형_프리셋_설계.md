# EP08: 슬라이더를 없애지 않고도 손 안 대게 만들기 — 문서 유형 프리셋 설계

**시리즈**: OCR 서비스구축 #8
**이 글을 읽고 나면**: 실측으로 찾은 최적값을 UI에 어떻게 노출할지 — 슬라이더를 숨기지 않으면서도 초심자가 매번 조절할 필요는 없게 만드는 프리셋 패턴과, "근거 있는 값"과 "추정치"를 UI에서 구분해서 보여주는 방법을 알 수 있습니다.

---

## 핵심 한 줄 요약
> EP06·EP07에서 찾은 카테고리별 최적 대비/샤프니스 값을 "문서 유형" 드롭다운으로 노출했다 — 촬영 영수증·촬영 손글씨·전자문서 PDF는 실측 근거가 있고, 스캔 문서는 표본이 없어 추정치라는 걸 UI 문구에 그대로 명시했다. 프리셋을 고르면 슬라이더 값이 채워지지만 잠기지는 않는다 — 사람이 수동으로 건드리면 "수동 조정"으로 자동 전환된다.

> **자주 묻는 질문**
> **Q. 그냥 문서 유형별로 값을 고정해버리면 안 되나요?** → 실측이 카테고리당 2~6개 표본이라, 모든 사용자의 모든 문서에 그대로 맞는다고 장담할 수 없다. 프리셋은 "좋은 출발점"이지 "무조건 정답"이 아니라서, 사용자가 자기 문서를 보고 미세 조정할 수 있는 여지(슬라이더 잠금 해제)를 남겨야 한다.
> **Q. 스캔 문서는 왜 실측값이 없나요?** → EP06의 로컬 표본 6장에 스캔 문서 카테고리가 아예 없었다(손글씨·긴문서·영수증만 있었음). 없는 근거를 있는 척 보여주는 것보다, "추정치"라고 정직하게 표시하는 게 낫다고 판단했다.
> **Q. "수동 조정"으로 자동 전환되는 로직이 왜 필요한가요?** → 사용자가 프리셋을 고른 뒤 슬라이더를 손으로 만졌는데 드롭다운엔 여전히 "촬영 영수증"이라고 남아있으면, 지금 값이 프리셋 값인지 사용자가 바꾼 값인지 헷갈린다. 실제로 적용 중인 값과 화면 표시가 항상 일치해야 신뢰할 수 있는 UI가 된다.

## 문제 상황

EP06·EP07에서 카테고리별 최적 대비/샤프니스 값을 실측으로 찾았다. 이제 이걸 어떻게 사용자에게 전달할지가 남았다. 두 가지 극단이 있다.

1. **슬라이더를 없애고 값을 고정**: 초심자는 편하지만, 정확도가 아쉬운 특이 케이스(역광 사진, 심하게 구겨진 영수증 등)를 만나면 손쓸 방법이 없다.
2. **슬라이더만 두고 값은 사용자가 알아서**: 유연하지만, 실측으로 찾은 최적값이 있다는 걸 사용자가 알 방법이 없어서 있으나 마나 한 정보가 된다.

절충안으로 "프리셋 드롭다운 + 슬라이더 둘 다 유지, 프리셋을 고르면 슬라이더가 그 값으로 채워지되 잠기지는 않는다"로 방향을 정했다.

## STEP 1: 프리셋 값 매핑 — 실측 근거를 그대로 이식

EP06·EP07의 최종 추천값을 그대로 매핑 테이블로 옮겼다.

```javascript
const DOC_TYPE_PRESETS = {
  photo_receipt:      { contrast: -20, sharpen: 8 },   // 로컬 실측(EP06)
  photo_handwriting:  { contrast: -20, sharpen: 73 },  // 로컬 실측(EP06)
  digital:            { contrast: -10, sharpen: 0 },   // 로컬 실측(EP06, longdoc)
  scan:               { contrast: 0,   sharpen: 20 },  // ⚠ 실측 표본 없음 — 추정치
};
```

`scan`(스캔 문서)만 값이 다른 세 항목과 성격이 다르다는 걸 변수 옆 주석으로도, UI 문구로도 명시했다.

## STEP 2: UI — 드롭다운 선택 시 슬라이더 채우기

```javascript
document.getElementById("docTypePreset").addEventListener("change", (e) => {
  const key = e.target.value;
  if (key === "manual") return;  // "수동 조정" 선택 시 아무것도 안 함
  const preset = DOC_TYPE_PRESETS[key];
  document.getElementById("contrastRange").value = preset.contrast;
  document.getElementById("sharpenRange").value = preset.sharpen;
  document.getElementById("contrastVal").textContent =
    (preset.contrast >= 0 ? "+" : "") + preset.contrast + "%";
  document.getElementById("sharpenVal").textContent = preset.sharpen + "%";
});
```

드롭다운에서 "촬영 영수증"을 고르면 대비·샤프니스 슬라이더가 즉시 -20%/8%로 이동한다. 이 값을 그대로 써도 되고, 슬라이더를 다시 손으로 조절해도 된다.

## STEP 3: 사용자가 슬라이더를 직접 만지면 "수동 조정"으로 되돌리기

프리셋을 고른 뒤 슬라이더를 손으로 조절했는데 드롭다운이 여전히 "촬영 영수증"으로 표시돼 있으면 혼란스럽다 — 지금 적용 중인 값이 프리셋값 그대로인지, 사용자가 바꾼 값인지 화면만 봐서는 알 수 없기 때문이다. 슬라이더 입력 이벤트에 드롭다운을 되돌리는 로직을 붙였다.

```javascript
["contrastRange", "sharpenRange"].forEach((id) => {
  document.getElementById(id).addEventListener("input", () => {
    document.getElementById("docTypePreset").value = "manual";
  });
});
```

이제 슬라이더 값을 조금이라도 건드리면 드롭다운이 자동으로 "수동 조정"으로 바뀐다. 화면에 보이는 상태와 실제로 적용될 값이 항상 일치한다.

## STEP 4: 근거 있는 값과 추정치를 UI 문구로 구분

드롭다운 옵션 이름과 힌트 문구에 "권장값 자동 채움"이라는 표현을 쓰고, 스캔 문서 옵션 아래에는 별도로 경고성 힌트를 달았다.

```html
<label for="docTypePreset">문서 유형(권장값 자동 채움)</label>
<select id="docTypePreset">
  <option value="manual">수동 조정</option>
  <option value="photo_receipt">촬영 영수증</option>
  <option value="photo_handwriting">촬영 손글씨</option>
  <option value="digital">전자문서 PDF</option>
  <option value="scan">스캔 문서 (추정치 — 실측 표본 없음)</option>
</select>
```

"권장값"이라는 단어를 쓴 건 의도적이다 — "정답값"이라고 하면 사용자가 무조건 믿고 조정을 포기할 수 있는데, 실측으로 찾은 좋은 출발점일 뿐 모든 케이스에 완벽하지는 않다는 뉘앙스를 남기고 싶었다. 스캔 문서는 옵션 이름 자체에 "추정치"라고 박아서, 다른 세 옵션과 신뢰도가 다르다는 걸 드롭다운을 열어보는 순간 바로 알 수 있게 했다.

## STEP 5: 왜 "정확도 우선"이 아니라 "투명성 우선"으로 설계했나

이 기능을 만들면서 계속 스스로에게 물었던 질문은 "스캔 문서 표본이 없는데 그냥 그럴듯한 값을 채워 넣으면 안 되나?"였다. 실제로 콘트라스트 0%/샤프니스 20%는 완전히 근거 없는 숫자는 아니다(다른 카테고리들의 중간값 정도로 추정한 것) — 그런데 이걸 다른 프리셋과 똑같은 방식으로("실측 권장값"인 것처럼) 보여주면, 나중에 스캔 문서 인식률이 안 좋다는 피드백이 왔을 때 "왜 이 값을 권장했는지" 스스로도 설명할 수 없는 상태가 된다.

**기능이 불완전할 때는 "완벽한 척"보다 "어디까지 확실하고 어디부터 추정인지 명시"하는 쪽이 장기적으로 신뢰를 지킨다** — 이 원칙은 이후 다른 기능(예: 도로명주소 자동 보정에서 confidence를 low/high로 구분해 표시한 것)에도 그대로 이어졌다.
