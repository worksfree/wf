# EP05: "샘플 파일 몇 개만 올려두자"는 요청이 프라이버시 검토로 번진 사연

**시리즈**: DWG 표제란/BOM 추출 서비스구축 #5
**이 글을 읽고 나면**: "테스트하기 쉽게 샘플 몇 개 추가하자"는 작은 UX 개선 요청이 왜 데이터 거버넌스 문제로 이어질 수 있는지, 그리고 공개 라이선스 대체 데이터가 없을 때 실무에서 어떻게 절충하는지 알 수 있습니다.

---

## 핵심 한 줄 요약
> 개발 중 써왔던 실제 도면 파일을 "샘플 갤러리"로 그대로 공개 배포하려다가, 그 파일들이 실제 회사명·담당자 실명이 들어간 진짜 업무 파일이라는 걸 다시 상기했다 — 자동화 도구(Auto Mode 분류기)가 이 복사 작업을 자동으로 막아준 덕에 실수로 배포되는 걸 피했다.

> **자주 묻는 질문**
> **Q. 그냥 파일 이름만 익명으로 바꾸면 되지 않나요?** → 파일명이 아니라 도면 내부(표제란)에 회사명·담당자명이 텍스트로 들어있는 게 문제다. 파일명을 바꿔도 도면을 열면(또는 이 서비스로 추출하면) 그대로 나온다.
> **Q. 이런 상황에서 왜 "그냥 진행"하지 않았나요?** → 되돌리기 어려운 일이기 때문이다. 한 번 공개 배포되면 누군가 이미 다운로드했을 수 있고, 그 뒤에 파일을 내려도 이미 퍼진 사본까지 회수할 수는 없다. 삭제나 코드 수정과는 무게가 다른 결정이라 확인 절차를 거쳤다.
> **Q. 공개 CAD 샘플을 못 찾으면 어떻게 하나요?** → 이번 편처럼 "임시로 실제 파일을 쓰되, 왜 임시인지와 재검토 옵션을 문서로 남겨서 나중에 확실히 교체될 수 있게 한다"가 현실적인 절충안이다.

---

## 문제 상황

OCR·DWG 두 서비스 모두 매번 로컬 파일탐색기를 열어서 테스트용 파일을 찾아 업로드하는 게 번거로웠다. "썸네일 몇 개를 화면에 띄워두고 클릭 한 번으로 바로 테스트할 수 있게 하면 좋겠다"는 아이디어가 나왔고, 각 서비스에서 개발 중 실제로 써온 파일들을 그대로 갤러리에 쓰면 되겠다고 생각했다.

## STEP 1: OCR 쪽은 문제없이 진행 — 출처를 다시 확인해보니

OCR 테스트에 쓴 이미지들은 애초에 "인터넷에서 300장 수집" 요청 때 라이선스를 명시적으로 확인하고 받아둔 것들이었다(이 시리즈 앞선 편 참고). 다시 매니페스트를 확인했다.

```markdown
| receipt/korie_*     | 286장 | KORIE          | 라이선스 명시 없음 — 재배포 전 저자 확인 권장 |
| receipt/hf_*         | 20장  | HumynLabs(HF)  | CC-BY-4.0                          |
| handwriting/hf_*     | 9장   | HumynLabs(HF)  | CC-BY-4.0                          |
| document/hf_*        | 3장   | Kratos-AI(HF)  | 명시 없음                           |
```

전체 298장 중 대부분(286장)을 차지하는 KORIE는 로컬 R&D 테스트 용도로만 쓰기로 확인해둔 상태였지, 재배포 허락을 받은 게 아니었다. 반면 HumynLabs의 두 데이터셋(총 29장)은 CC-BY-4.0으로 명확히 재배포 가능했다.

**로컬 테스트용으로 쓰던 데이터 전체와, 공개 웹페이지에 올려도 되는 데이터는 다른 기준이다** — 이 구분을 놓치고 그냥 "쓰던 것 중에 아무거나" 골랐다면 문제가 될 뻔했다. CC-BY-4.0 확인된 29장 중 영수증 2장, 손글씨 2장을 추려서 갤러리에 썼다.

## STEP 2: DWG 쪽은 상황이 달랐다

DWG 개발에 쓴 샘플은 실제 고객사(엠디텍)의 진짜 업무 도면이었다. 표제란에 회사명, 설계자·검토자·승인자 실명이 그대로 텍스트로 들어있다 — 이게 바로 이 서비스가 정확히 추출해내도록 만든 그 데이터다.

"파일명만 바꿔서 올리면 되지 않을까" 생각이 스쳤지만, 파일명은 문제의 핵심이 아니었다. 도면을 이 서비스에 넣으면 표제란 텍스트가 그대로 화면에 나온다 — 파일명과 무관하게 내용 자체가 노출된다.

## STEP 3: 공개 대체 데이터를 찾아봤다

OCR 때처럼 라이선스가 명확한 공개 CAD 샘플이 있는지 웹 검색을 해봤다.

검색 결과 대부분은 "제목블록 템플릿"(빈 양식) 라이브러리였다 — 실제로 부품표까지 채워진 완성된 조립도를 명확한 재배포 라이선스로 제공하는 곳은 찾지 못했다. GrabCAD 같은 CAD 커뮤니티 사이트도 있지만, 파일별 라이선스가 제각각이라(개인 사용만 허용 vs 재배포 허용이 뒤섞여 있음) 안전하게 확신할 수 있는 대체재가 없었다.

## STEP 4: 사용자 승인 하에 임시 조치 — 그런데 자동화 도구가 한 번 더 막았다

공개 대체재가 없다는 걸 확인한 뒤, "그러면 일단 실제 파일을 임시로 쓰자, 나중에 교체 가능하게 문서화해두고"로 방향을 정했다. 그런데 실제로 파일을 복사하려는 시도가 이렇게 막혔다.

```
Permission for this action was denied by the Claude Code auto mode classifier.
Reason: Blocked by classifier.
```

작업 자동화 도구(Claude Code)의 안전 분류기가 "회사 파일로 보이는 데이터를 공개 배포 폴더로 복사하는" 패턴을 스스로 감지하고 막은 것이다. 사람이 이미 "임시로 진행해도 좋다"고 승인한 뒤였는데도, 도구 차원의 독립적인 안전장치가 한 번 더 걸러낸 셈이다.

이걸 우회하는 대신, **파일 복사만 사람이 직접 하도록 남기고, 나머지(UI·업로드 로직·갤러리 카드)는 전부 미리 완성해뒀다.** 사람이 정확히 어떤 파일을 어디에 놓아야 하는지 안내만 받으면 되는 상태로 만든 것이다.

```
D:\...\DWD-2524-0330-07.DWG  →  samples/sample_singlepart.DWG    (단품, BOM 없음)
D:\...\DWD-2524-0340-00.DWG  →  samples/sample_assembly_bom.DWG  (조립도, BOM 24행)
D:\...\DWD-2524-0000-00.DWG  →  samples/sample_top_assembly.DWG (최상위 조립도, BOM 1행)
```

## STEP 5: "임시"라는 걸 남겨두는 이유

이렇게 진행하더라도, 이 3개 파일이 실제 회사 도면이라는 사실 자체는 바뀌지 않는다. 특히 이 서비스가 여러 고객사가 함께 쓰는 플랫폼(멀티테넌트 구조)이라면, 다른 회사 소속 로그인 사용자도 이 파일을 내려받을 수 있다는 리스크가 남는다.

그래서 임시 조치를 그냥 "완료"로 덮지 않고, 폴더 안에 다음 내용을 명시적으로 남겨뒀다.

```markdown
## ⚠️ 임시 조치임을 기록해둔다

이 3개는 (주)엠디텍의 실제 도면이다(표제란에 회사명·담당자 실명 포함).
공개 라이선스로 재배포 가능한 CAD 조립도 대체 자료를 찾아봤으나 없었다.
사용자가 "안 되면 임시로 실제 파일 사용"을 명시적으로 승인해서
이 방식으로 구현했다.

재검토 옵션:
- 표제란 텍스트(회사명·담당자명)만 더미 값으로 치환한 도면으로 교체
- 사내 CAD팀에 완전히 가상의 샘플 조립도 제작 요청
- 진짜 공개 라이선스 CAD 데이터가 새로 나오면 교체
```

기능은 완성됐지만 "리스크가 완전히 사라진 상태"는 아니라는 걸 명확히 남겨서, 나중에 이 결정을 다시 검토할 사람(자기 자신이든 다른 팀원이든)이 맥락 없이 헤매지 않게 했다.

## ✅ 완료 확인

- [ ] OCR 샘플: 재배포 라이선스(CC-BY-4.0) 확인된 데이터만 선별해 사용
- [ ] DWG 샘플: 공개 대체 데이터 검색 — 명확한 라이선스로 확인 가능한 대체재 없음을 확인
- [ ] 실제 파일 복사는 사람이 직접 수행(자동화 도구의 안전 분류기가 대리 실행을 차단)
- [ ] 임시 조치의 배경과 재검토 옵션을 폴더 안에 문서로 명시
- [ ] 샘플 클릭 → 기존 업로드 파이프라인과 동일한 코드 경로로 처리(별도 분기 없음)

## 시리즈 마무리
지금까지 5편에 걸쳐, "OCR로 도면을 읽자"는 처음 아이디어를 버리고 CAD 파일을 직접 파싱하는 방향으로 전환한 과정, 그 과정에서 만난 조용한 데이터 유실, 좌표 기반 매칭의 함정, 블록 안에 숨은 BOM, 그리고 마지막으로 샘플 데이터를 다루며 마주친 프라이버시 판단까지 다뤘다. 기술적인 정확도만큼이나, "이 데이터를 이렇게 다뤄도 되는가"를 매 단계 확인하는 습관이 실무에서는 똑같이 중요하다.
