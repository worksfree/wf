# EP01: 도면을 눈으로 넘겨보는 대신, 좌표로 대조할 수 있을까 — PCB 발주 전 검증 자동화의 첫 질문

**시리즈**: PCB 설계검증 자동화 서비스구축 #1
**이 글을 읽고 나면**: PCB를 주문 제작할 때 무엇을·어떤 절차로 검증해야 하는지, 그리고 도면(DXF) 안의 좌표 데이터만으로 핀 연결 여부를 자동으로 대조하는 방식이 왜 가능한지 — 그리고 어디까지만 가능한지를 알 수 있습니다.

---

## 핵심 한 줄 요약
> PCB 발주 후 검증은 지금도 대부분 "거버 파일을 사람이 눈으로 훑어보는" 방식에 머물러 있다. 그런데 도면 안의 선·텍스트가 이미 좌표를 가진 벡터 데이터라는 사실은 DWG 표제란 추출 시리즈에서 확인했던 것과 정확히 같다 — 핀 이름 텍스트와 거기서 뻗어나온 선의 좌표가 얼마나 가까운지만 계산하면, 스펙 파일과 도면의 연결 관계를 사람 대신 기계가 1차로 대조할 수 있다는 뜻이다.

> **자주 묻는 질문**
> **Q. 거버(Gerber)/DFM 검증은 제조사가 다 해주지 않나요?** → 제조사 DFM 리포트는 "제조가 가능한가"(선폭·선간격, 최소 홀 크기, 애뉼러링 두께)를 확인해줄 뿐이다. "내가 의도한 대로 실제 연결됐는가"는 별개 문제이고, 그건 여전히 발주자 책임이다.
> **Q. DXF에는 원래 넷리스트(연결 정보)가 들어있는 거 아닌가요?** → 없다. DXF는 순수 2D 기하 도면 포맷이라 "이 선이 어떤 핀과 어떤 핀을 연결하는지"에 대한 의미론적 정보 자체가 없다. 사람이 텍스트와 좌표를 보고 유추하거나, 도면을 처음부터 규칙적으로 그려야만 기계가 같은 방식으로 유추할 수 있다.
> **Q. 그러면 아무 도면에나 이 방식을 적용할 수 있나요?** → 아니다. 핀 라벨이 텍스트로 존재하고 그 좌표가 배선 끝점과 가까워야 하거나(방식 A), 커넥터가 블록으로 지정되고 핀 번호가 속성(ATTRIB)으로 들어 있어야(방식 B) 적용 가능하다. 규칙 없이 자유롭게 그린 도면에는 적용할 수 없다.

---

## 문제 상황

기구설계자가 PCB를 발주할 때 실제로 검증하는 과정을 들여다보면 이렇다. 거버 뷰어를 열어 레이어 수·외곽선·드릴 위치를 눈으로 확인하고, 제조사가 보내주는 DFM 리포트를 받아 선폭이나 홀 크기 경고를 확인한다. 여기까지는 전문 CAM 소프트웨어와 제조사의 검수 프로세스가 이미 상당 부분을 대신해준다.

그런데 "내가 회로도대로 커넥터 핀을 정확히 연결했는가"는 여전히 다른 문제다. 이건 제조사가 확인해주지 않는다 — 제조사는 이 보드가 뭘 해야 하는지 모르고, 단지 도면대로 물리적으로 만들 수 있는지만 본다. 결국 발주자가 도면을 몇 번이고 다시 열어 커넥터 핀 하나하나를 눈으로 짚어가며 스펙 문서와 대조해야 한다. 핀이 수십~수백 개인 도면이라면 이 작업만으로도 상당한 시간이 든다 — 이는 [DWG 표제란/BOM 추출 시리즈](../DWG추출서비스-콘텐츠/)의 출발점이었던 "반복 작업" 문제와 정확히 같은 종류다.

## STEP 1: 검증해야 할 항목부터 5가지로 정리한다

무작정 자동화를 고민하기 전에, PCB 발주 검증이 실제로 몇 개의 서로 다른 문제로 이루어져 있는지부터 나눠봤다.

1. **거버/ODB++ 교차검증** — 레이어 스택업, 외곽선·치수, 드릴 데이터가 주문서와 일치하는지
2. **DFM(Design for Manufacturing)** — 최소 선폭/선간격, 최소 홀 크기·애뉼러링, 솔더마스크 오픈이 제조 한계 안에 있는지
3. **주문서 사양서 텍스트 대조** — 동박 두께, 표면 처리(HASL/ENIG/OSP), 보드 두께·재질이 문서와 일치하는지
4. **넷리스트 교차검증** — 회로도의 연결 정보와 최종 거버의 연결 정보가 일치하는지(IPC-D-356)
5. **제조사 DFM 리포트 검토** — 전문 CAM 소프트웨어가 잡아주는 자체 리포트를 EQ(Engineering Query) 단계에서 확인

## STEP 2: 이 중 "내 눈"으로만 되는 부분이 어디인지 짚는다

다섯 항목을 자동화 가능성 기준으로 다시 나눠보면 성격이 확연히 다르다.

- **1·2·5**는 이미 전문 CAM 뷰어와 제조사의 DFM 엔진이 대신해준다. 발주자가 새로 자동화할 필요가 상대적으로 적다.
- **3**은 단순 텍스트 대조라 스크립트로 쉽게 자동화된다 — 주문서 사양서와 거버 텍스트(readme.txt 등)를 파싱해서 문자열만 비교하면 된다.
- **4**가 문제다. 넷리스트 교차검증은 "회로도 데이터(넷리스트)"가 있어야 성립하는데, 발주자 손에 회로도 데이터 없이 **도면(DXF) 한 장만** 있는 상황이면 이 검증 자체를 할 방법이 없어 보인다.

여기서 질문이 하나 남는다 — 회로도 파일이 없어도, 도면 자체에서 "핀 연결 정보"를 읽어낼 수 있을까.

## STEP 3: DXF는 회로 데이터가 아니다 — 그런데도 자동화가 되는 조건

먼저 확실히 짚어야 할 전제가 있다. **DXF는 순수 2D 기하 도면 포맷이지 넷리스트가 아니다.** 선(LINE)과 텍스트(TEXT)의 좌표만 들어있을 뿐, "이 선이 회로적으로 어떤 신호를 나타내는지"는 애초에 저장되지 않는다.

이 대목에서 [DWG 시리즈 EP02](../DWG추출서비스-콘텐츠/ep02_DXF_변환의_함정.md)에서 확인했던 것과 같은 조심스러움이 다시 필요하다. 그때는 `dwg2dxf` 변환 과정에서 MTEXT의 77%가 조용히 사라지는 걸 뒤늦게 발견했었다. 다만 이번 경우는 상황이 조금 다르다 — PCB 설계 도면은 처음부터 CAD 툴에서 DXF로 저장되므로 그 "변환 손실" 문제 자체가 없다. 대신 이번엔 "애초에 그 안에 회로 의미 정보가 없다"는, 변환 손실과는 또 다른 종류의 한계를 마주하게 된다.

그런데도 완전히 손을 놓을 필요는 없다. 도면이 아래 두 조건 중 하나로 작성되어 있다면 핀 연결 정보를 근사적으로 추출할 수 있다.

- **방식 A (텍스트 매칭)**: 선(LINE/POLYLINE)의 양 끝점 좌표 위치에 핀 번호나 신호 이름(TEXT/MTEXT)이 겹쳐서(또는 아주 가깝게) 적혀 있는 경우
- **방식 B (블록 속성 매칭)**: 커넥터가 하나의 블록(INSERT)으로 지정되어 있고, 그 안에 핀 번호·좌표가 속성(ATTRIB)으로 들어 있는 경우

즉 "회로도 데이터가 없어도 된다"가 아니라, "도면 자체가 회로도를 겸해서 규칙적으로 그려져 있다면 그 규칙을 역이용할 수 있다"는 조건부 자동화다.

## STEP 4: 개념검증 — 스펙 파일과 도면을 좌표로 대조하기

방식 A를 기준으로 최소한의 로직을 그려보면 이렇다. `ezdxf`로 도면에서 선과 텍스트를 추출하고, 텍스트 좌표에서 오차범위 이내에 있는 선의 끝점을 "그 핀과 연결된 선"으로 판정한 뒤, 스펙 파일(엑셀)에 정의된 정상 연결 목록과 대조한다.

```python
import ezdxf
import pandas as pd
import math

def get_distance(p1, p2):
    return math.sqrt((p1[0] - p2[0])**2 + (p1[1] - p2[1])**2)

def run_pin_verification(dxf_path, spec_excel_path, tolerance=1.0):
    spec_df = pd.read_excel(spec_excel_path)
    spec_connections = set(zip(spec_df['From_Pin'], spec_df['To_Pin']))

    doc = ezdxf.readfile(dxf_path)
    msp = doc.modelspace()

    # 핀 레이블 텍스트와 좌표 수집
    pins = [{"name": t.dxf.text, "pos": t.dxf.insert[:2]}
            for t in msp.query("TEXT MTEXT")]

    # 선의 양 끝점에서 오차범위(tolerance) 이내의 핀을 찾아 연결쌍 구성
    detected = set()
    for line in msp.query("LINE"):
        start, end = line.dxf.start[:2], line.dxf.end[:2]
        from_pin = next((p["name"] for p in pins if get_distance(start, p["pos"]) < tolerance), None)
        to_pin   = next((p["name"] for p in pins if get_distance(end,   p["pos"]) < tolerance), None)
        if from_pin and to_pin:
            detected.add(tuple(sorted([from_pin, to_pin])))

    # 스펙 대비 Pass/Fail 판정
    for a, b in spec_connections:
        status = "OK" if tuple(sorted([a, b])) in detected else "FAIL — 연결 누락 또는 오연결"
        print(f"[{status}] {a} <-> {b}")
```

핵심은 두 줄로 요약된다 — **좌표 근접도로 "어떤 텍스트와 어떤 선 끝점이 사실상 같은 위치에 있는가"를 판정**하고, 그렇게 얻어진 연결쌍을 **스펙 파일과 집합(set) 비교**한다. 회로 의미를 이해할 필요 없이 기하학적 근접성만으로 1차 스크리닝이 가능하다는 뜻이다.

## STEP 5: 한계와 실전 튜닝 포인트

개념은 성립하지만 실전에 붙이려면 최소 두 가지를 반드시 튜닝해야 한다.

- **오차범위(tolerance) 설정**: CAD 도면 특성상 선의 끝점과 텍스트 삽입점이 소수점 단위로 미세하게 어긋난다. 너무 좁히면 정상 연결도 놓치고(오탐 FAIL), 너무 넓히면 서로 다른 핀을 같은 것으로 오판한다. 0.5~1mm 사이에서 실제 도면으로 실측 조정이 필요하다.
- **레이어 분리**: 핀 텍스트와 배선이 각각 전용 레이어(예: `LAYER_PIN_TEXT`, `LAYER_SIGNAL`)로 구분되어 있다면 `msp.query('LINE[layer=="LAYER_SIGNAL"]')`처럼 특정 레이어만 타겟팅해서 속도와 정확도를 동시에 높일 수 있다.

그리고 가장 중요한 전제 하나 — **이 방식은 "도면이 규칙적으로 그려졌을 때"만 성립**한다. 핀 이름이 텍스트로 존재하지 않거나 좌표가 불규칙하게 흩어진 도면에는 적용할 수 없다. 이번 편은 이 조건을 먼저 확인하는 단계였고, 실제 커넥터 도면으로 이 로직을 검증하는 건 다음 편 몫이다.
