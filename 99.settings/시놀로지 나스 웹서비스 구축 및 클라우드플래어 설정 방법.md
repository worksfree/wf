## 1. 운영 원칙: Cloudflare와 Tailscale의 완벽한 조화

이 매뉴얼의 핵심은 **"공유기 포트 포워딩 없이 안전하게 외부망을 개방"**하는 것입니다. 목적에 따라 두 가지 서비스를 병행(동시) 사용하는 것이 가장 스마트하고 안전한 운영 방식입니다.

| 구분 | Cloudflare Tunnel (웹 배포용) | Tailscale (관리 및 대용량 작업용) |
| :--- | :--- | :--- |
| **목적** | 외부인/고객에게 웹사이트 공개 | 관리자 본인의 NAS 시스템 접속 및 파일 관리 |
| **접속 방식** | 일반 도메인 (`staging.worksfree.kr`) | Tailscale 부여 IP (`100.x.x.x`) |
| **장점** | 접속자가 앱을 깔 필요 없음, **자동 HTTPS** | NAS 전체 접근 가능, 완전한 비공개망 |
| **단점(제약)** | 무료 요금제는 **단일 파일 업로드 100MB 제한** | 접속하려는 모든 기기에 Tailscale 앱 설치 필수 |

> **💡 운영 팁:** 홈페이지 접속 테스트나 대중 배포는 `Cloudflare`로 뚫어둔 도메인을 사용하고, NAS의 제어판(DSM) 접속이나 무거운 파일 업로드는 `Tailscale`로 접속하세요!

## 2. 1단계: 웹 서버 기초 확인 (Web Station)

Cloudflare로 길을 뚫기 전에, 내부에서 목적지가 될 웹사이트가 잘 돌아가고 있어야 합니다.
1. NAS 패키지 센터에서 **Web Station**을 설치하고 웹 서비스를 생성합니다.
2. NAS 내부망(Wi-Fi) 환경에서 `http://NAS내부IP:포트번호` (예: `http://192.168.0.10:8080`)로 접속했을 때 만든 홈페이지가 정상적으로 뜨는지 미리 확인합니다.

---

## 3. 2단계: 도메인 네임서버 변경 (DNS 이관)

도메인(`worksfree.kr`)의 목적지 안내 역할을 가비아에서 Cloudflare로 넘겨주는 작업입니다.

1. **Cloudflare에 사이트 추가**: 로그인 후 `[Add a Site]`에 `worksfree.kr` 입력 → Free(무료) 요금제 선택.
2. **DNS 스캔 결과 확인 (당황 금지!)**: 
   * **검색된 레코드가 `0`개로 나와도 절대 정상입니다.** 그냥 `[Continue]`를 눌러 팝업에서 확인을 누르고 과감히 넘어가세요.
3. **네임서버(Nameserver) 변경**:
   * 가비아 로그인 → `worksfree.kr` 도메인 관리 → 네임서버 설정 진입.
   * 기존 네임서버 1차~4차를 모두 지웁니다.
   * Cloudflare에서 부여받은 **고유 네임서버 2개**를 입력하고 저장합니다.
     * 1차: `keaton.ns.cloudflare.com`
     * 2차: `zita.ns.cloudflare.com`
   * *※ 변경 반영까지는 짧게는 10분, 길게는 수 시간이 소요될 수 있습니다.*

## 4. 3단계: NAS에 터널 커넥터(Docker) 설치하기

1. **터널 생성**: Cloudflare Dashboard → `[Zero Trust]` → `[Networks]` → `[Tunnels]` → `[Create a tunnel]` 클릭. 터널 이름(예: `synology-tunnel`)을 입력합니다.
2. **운영체제 환경 선택 (🚨실수 방지 포인트!)**:
   * 화면에 Windows `.msi` 다운로드가 기본으로 뜰 수 있습니다. 당황하지 말고 상단 운영체제 선택란에서 🐋 **[Docker] 아이콘을 반드시 클릭**하세요.
3. **토큰(Token) 복사**:
   * 화면에 뜨는 명령어 중 `--token` 뒤에 붙어있는 **아주 긴 영문+숫자 문자열만 복사**합니다.
4. **시놀로지 NAS 설정**:
   * NAS `Container Manager` 실행 → `[프로젝트]` → `[생성]`.
   * 아래의 Docker Compose 코드를 입력합니다. (복사한 토큰 값 붙여넣기)

```yaml
version: '3.9'
services:
  cloudflare-tunnel:
    container_name: cloudflare-tunnel
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: tunnel --no-autoupdate run --token 당신의_복사된_긴_토큰값_입력
```

## 5. 4단계: 웹사이트 라우팅 (외부 주소 ↔ 내부 NAS 연결)

가장 실수가 잦은 구간입니다. 터널이 연결(Status: HEALTHY)되었다면, 도메인과 NAS의 포트를 연결합니다.

1. 생성한 터널 클릭 후 **[Configure] (구성)** 버튼 클릭.
2. **메뉴 선택 (🚨실수 방지 포인트!)**: 
   * 상단 탭에서 ❌ `Hostname routes Beta` 가 아니라 ⭕ **`[Published application routes]`** (또는 Public Hostname)를 클릭해야 합니다. (Beta 메뉴는 기업 내부망 전용입니다.)
3. **[Add a published application route]** 클릭 후 아래와 같이 입력:

| 입력 항목 | 입력 값 예시 | 설명 및 주의사항 |
| :--- | :--- | :--- |
| **Subdomain** | `staging` | 접속할 서브도메인 이름 |
| **Domain** | `worksfree.kr` | 목록에서 선택 |
| **Path** | (빈칸) | |
| **Service Type** | `HTTP` | 내부 서비스가 HTTP라면 그대로 선택 |
| **Service URL** | `http://192.168.0.x:8080` | 🚨 **주의: `localhost:8080` 금지!** Docker 환경이므로 반드시 **NAS의 실제 내부망 IP 주소**를 적어야 502 Bad Gateway 오류가 나지 않습니다. |

4. 저장 후 스마트폰의 와이파이를 끄고 외부망(LTE/5G)에서 `https://staging.worksfree.kr` 접속을 확인합니다.

## 6. 5단계: 확장 및 유지보수 (test 도메인 추가 및 포트 변경)

이 세팅의 가장 큰 장점은 도메인 하나로 무한대의 접속 경로를 만들 수 있다는 점입니다.

### Q. `test.worksfree.kr`을 새로 추가하려면?
1. Cloudflare `[Networking]` → `[Tunnels]` 메뉴에서 내 터널(`synology-tunnel`)의 **[Configure]** 클릭.
2. **[Overview] [Routes]** 중에 **[Routes]** 탭을 클릭.
3. 우측에 **...** 클릭 후 **[Edit route]** 버튼을 클릭.
4. 설정값 입력:
   * **Subdomain**: `test` (원하는 서브도메인)
   * **Domain**: `worksfree.kr`
   * **Service URL**: 테스트 서버가 돌아가고 있는 NAS 내부 IP와 해당 포트 (예: `http://192.168.100.38:8081`)
5. [Save] 버튼을 누르면 즉시 `test.worksfree.kr` 도메인 연결이 완료됩니다.
6. 추가 확장시 순서 : 
   1. Cloudflare : Networking > Tunnels > *synology-tunnel* > Routes > Add route > Published application
   2. Synology NAS : Web Station > 웹 서비스 > "다음" 클릭 > 이름, 설명, 문서 루트(폴더 경로), 백엔드 NginX > 생성 =======> 제작한 html 페이지를 해당 폴더에 업로드
   3. Synology NAS : Web Station > 웹 포털 > 웹 서비스 설정 > 포털 유형(포트 기반) > HTTP: 808x > 생성 

### Q. 이미 연결된 설정의 '포트 번호'나 대상을 수정하려면?
1. 동일하게 **[Published application routes]** 탭으로 들어갑니다.
2. 목록에서 수정할 도메인(`staging.worksfree.kr`) 우측의 **[Edit] (수정)** 버튼을 클릭합니다.
3. Service 항목의 **URL(IP나 포트 번호)**을 원하는 새로운 값으로 지우고 다시 적습니다.
4. [Save]를 누르면 즉시 목적지가 변경됩니다.

## 7. 💡 필수 대체 용어 사전 (UI 변경 대비)

IT 플랫폼인 Cloudflare는 메뉴 이름(UI)을 자주 업데이트합니다. 차후 접속 시 메뉴 이름이 바뀌어 있더라도 당황하지 않도록 유사 용어를 정리해 드립니다.

* **외부 접속용 도메인 연결 탭**: `Public Hostname` ↔ `Published application routes` (둘 다 외부 대중의 접근을 허용하는 라우팅 메뉴를 뜻합니다.)
* **터널 프로그램 이름**: `Connector` ↔ `Cloudflared` ↔ `Agent` (NAS에 설치되어 Cloudflare망과 통신하는 도커 컨테이너를 지칭합니다.)
* **사설망/내부망 메뉴 (웹사이트 배포 시 무시할 것)**: `Private Networks` ↔ `Hostname routes Beta` ↔ `CIDR routes` (일반 대중에게 웹사이트를 공개하는 용도가 아니므로 들어가지 않습니다.)
