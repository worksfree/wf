# AI-Hub 업종별 OCR 샘플 다운로드 가이드

2026-07-23 새벽에 유통/요식/제조업 OCR 테스트 데이터셋 목록을 받아 자동 다운로드 및 테스트를 시도했으나, **AI-Hub는 계정 본인인증 + 데이터셋별 "사용 목적" 승인 심사를 반드시 거쳐야** 해서 에이전트가 무인으로 처리할 수 없다. 확인된 사실(2026-07-23 실측 웹 조회):

- 회원가입 자체는 즉시 가능하고, API 키(`aihubshell` 다운로드 도구용)도 가입 즉시 이메일로 발급됨.
- **하지만 실제 데이터 다운로드는 데이터셋 하나하나마다 "사용 목적" 신청 → 검토 → 승인 완료가 필수**다. 샘플(경량) 데이터도 예외라는 공식 언급이 없다 — 즉 승인 없이 그냥 받아지는 게 아닐 가능성이 높다.
- 승인 심사는 "부적합 판단 시 거부될 수 있다"고 명시돼 있어 사람이 직접 목적을 작성해 제출해야 하고, 승인까지 즉시가 아닐 수 있다(문의처: `safezone1@aihub.kr`, 02-525-7708/7709).

**결론**: 본인인증·목적 심사는 계정 소유자 본인만 할 수 있는 절차라 이 부분은 사람이 직접 처리해야 한다. 아래는 그 작업을 최대한 짧게 끝낼 수 있도록 정리한 단계별 가이드이고, 승인이 끝난 뒤 폴더에 파일만 떨어뜨리면 나머지(전처리 파라미터 스윕·정확도 측정·리포트 생성)는 `ingest_aihub_samples.py`가 전부 자동으로 처리한다.

## 1. 회원가입 + API 키 발급 (5분)

1. https://aihub.or.kr 접속 → 회원가입 (본인인증 필요)
2. 로그인 후 **마이페이지 → API 키 발급** 클릭 → 이메일로 키 수신
3. `aihubshell` 다운로드:
   ```powershell
   curl -o aihubshell.exe https://api.aihub.or.kr/api/aihubshell.do
   ```
   (Windows에서 실행이 안 되면 WSL/Git Bash에서 `curl -o aihubshell ... && chmod +x aihubshell` 후 실행)

## 2. 데이터셋 검색 + 신청 (데이터셋당 5~10분)

받은 목록 중 우선순위 3개만 먼저 신청 — 전부 한 번에 신청하면 검토가 늦어질 수 있으므로 업종당 1개씩만 골라 빠르게 승인받고, 필요하면 나중에 추가 신청한다.

| 우선순위 | 검색어 | 업종 | 비고 |
|---|---|---|---|
| 1 | `한국어 글자체 이미지` 또는 `KORIE` | 유통(영수증) | 이번 세션에서 이미 검증된 영수증 인식 파이프라인과 바로 비교 가능 |
| 2 | `금융업 특화 문서 OCR` | 요식업(구겨진 영수증) | 실측 목표였던 "구겨진 영수증" 취약점 직접 보강 |
| 3 | `OCR 데이터(공공행정)` | 제조업(수기 인수증) | 손글씨 카테고리 보강 |

각 데이터셋 상세 페이지에서:
1. **다운로드** 버튼 클릭 → 로그인 요구 시 로그인
2. **"샘플데이터(경량)"** 옵션이 보이면 그것부터 선택 (용량 작고 승인이 더 쉬울 가능성)
3. 신청서 작성 — **사용 목적**란에 아래 문구를 그대로 복사해 써도 된다(사실 그대로임):
   > 자사(중소기업) 내부용 OCR 서비스의 문서 인식 정확도를 검증하기 위한 비상업적 연구·개발 목적입니다. 로컬 PC 환경에서 오픈소스 OCR 모델(olmOCR-2)의 전처리 파라미터(대비·샤프니스) 최적값을 실측으로 찾는 데 사용하며, 데이터를 제3자에 제공하거나 재배포하지 않습니다.
4. 제출 → 승인 대기 (승인 알림은 이메일/마이페이지로 옴)

## 3. 승인 후 다운로드

```powershell
# API 키는 최초 1회만 등록
.\aihubshell.exe -mode l                       # 로그인 (API 키 입력)
.\aihubshell.exe -mode ds                      # 승인된 데이터셋 목록 확인
.\aihubshell.exe -mode d -datasetkey <번호>     # 다운로드 (분할 압축 파일로 받아짐)
```

분할 압축 파일은 다운로드 완료 후 자동/수동으로 병합 압축 해제해야 한다(`aihubshell` 도움말의 병합 안내 참고).

## 4. 압축 해제 후 이 폴더 구조로 정리

`ingest_aihub_samples.py`가 자동으로 인식하는 구조:

```
10.rpa/70.webs/ocr-eval/aihub_samples/
├── retail/           # 유통업 — 거래명세서·영수증류 이미지
│   ├── img001.jpg
│   ├── img001.json   # 있으면 자동으로 정답 텍스트 추출 시도 (없어도 동작은 함)
│   └── ...
├── fnb/              # 요식업 — 구겨진 영수증·손글씨 발주서
│   └── ...
└── manufacturing/    # 제조업 — 도면·검사성적서·수기 인수증
    └── ...
```

- 각 하위 폴더 이름(`retail`/`fnb`/`manufacturing`)이 그대로 카테고리로 쓰인다.
- 이미지 파일만 넣어도 동작하지만(전처리 파라미터 최적값은 찾을 수 있음), **정답 텍스트가 없으면 CER(정확도) 채점은 불가능** — AI-Hub 데이터셋에 포함된 어노테이션 JSON에서 텍스트 필드를 자동 추출 시도하지만, 데이터셋마다 스키마가 달라 완벽하지 않을 수 있다. 안 되면 직접 `img001.txt`로 정답을 만들어 같은 폴더에 넣어도 인식한다.

## 5. 실행

```powershell

```

`sweep_report.md`에 업종별(유통/요식/제조) 최적 콘트라스트·샤프니스 값과, 이번에 로컬 6종 표본(손글씨·긴문서·영수증)으로 이미 찾은 값과의 비교가 함께 나온다.

## 참고 — 왜 완전 자동화가 안 되는지 (요약)

에이전트가 브라우저 로그인·본인인증·목적 심사 제출을 대신 할 수 없는 이유는 기능 제약이 아니라 **정책상 이유**다: 본인인증은 계정 소유자 신원 확인이 목적이라 대리 수행 시 정책 위반이고, 목적 심사는 신청자 본인이 실제로 그 목적으로 쓸 것이라는 진술이라 대리 작성 시 사실과 다른 진술이 될 수 있다. 이 두 단계만 사람이 처리하면, 그 이후(다운로드~정확도 측정~리포트)는 전부 스크립트로 자동화돼 있다.
