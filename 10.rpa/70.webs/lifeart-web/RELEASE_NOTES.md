프리미엄 포토 서비스(포토북·삽입식 앨범·VIP 앨범·액자) 온라인몰 구축 프로젝트.
근무일 기준 10일(2주) 개발을 **5단계 릴리스**로 나누어 배포합니다.
(배포 방식: `pre-test`에서 전 기능 검수 → `test`로 `-Stage N` 단계 공개 → `production`)

## Stage 1 — 기반 구축 & 카탈로그 (Day 1–2)  · v0.1.x

이번 단계는 **눈에 보이는 화면보다 "보이지 않는 뼈대"에 대부분의 공수가 투입**되었습니다.
LifeArt는 WorksFree가 이미 운영 중인 Supabase 백엔드를 **비용 효율을 위해 공유**하기로 하여,
기존 서비스에 **사이드 이펙트 없이** LifeArt 데이터를 완전히 분리해내는 **멀티테넌트(multi-tenant) 전환**이 최대 과제였습니다.

### 멀티테넌트 DB 아키텍처 (핵심 작업)
- 공유 DB 감사 결과 **3가지 테넌트 규약이 혼재**(`tenant_id TEXT` / `tenant_id uuid FK` / `env`)하고,
  `profiles`에는 테넌트 구분 자체가 없으며 일부 테이블에 RLS가 없는 상태를 확인.
- **번호순 마이그레이션 스크립트(00~09)**로 무중단·검증형 전환 수행:
  - `tenants` 레지스트리 정비 + `lifeart.ai.kr` 테넌트 등록
  - 전 테이블에 `tenant_id` 부여 및 기존 데이터 안전 백필(worksfree 귀속), 이후 `NOT NULL` 강제
  - Row Level Security(RLS)로 **테넌트 간 데이터 완전 격리** — 각 테넌트는 자기 데이터만 조회/수정
  - 노출돼 있던 백업 테이블·연락처 테이블·캠페인 RPC **잠금(REVOKE/RLS)**
- 발견·수정한 대형 이슈: `profiles.role` 기본값 오류로 **모든 신규 가입이 500 에러**로 실패하던 버그를 근본 수정.
- 회귀 테스트 매트릭스로 **기존 WorksFree 허브 전 기능(가입·관리자·크레딧·자산관리·경매·캠페인)이 무손상**임을 검증.

### 프론트 (카탈로그 기반)
- 디자인 시스템(딥 차콜 + 뮤티드 골드) 및 공통 헤더/푸터·레이아웃 확립.
- **LifeArt 소개**(이야기·CEO·오시는 길·보도자료), **상품**(포토북·삽입식·VIP·액자), **제작과정** 카탈로그 페이지.
- 상품 시딩(액자 44종 등), 작품 갤러리·카탈로그 다운로드.

## Stage 2 — 회원 · 비즈니스 · 소셜 로그인 (Day 3–4)  · v0.2.x

Stage 1에서 닦은 멀티테넌트 기반 위에 **회원 시스템**을 올리는 단계로,
여기서도 "공유 DB에서 LifeArt 회원만 안전하게 분리"하는 작업이 이어졌습니다.

### 멀티테넌트 회원 (심화)
- Supabase Auth의 `auth.users`는 전 테넌트 공용이므로, **`profiles.tenant_id`로 LifeArt 회원을 식별**하는 구조 확정.
- 신규 가입 트리거가 만든 기본 프로필을 LifeArt 테넌트로 **클레임**하고, 타 테넌트(허브) 계정으로의
  교차 로그인은 **명확히 거부**하도록 처리.
- 관리자 권한 분리: 공유 `admin_*` RPC를 통해 **LifeArt 관리자가 허브 관리자로 승격되는 보안 구멍**을 발견,
  `is_admin()`을 worksfree 테넌트로 스코핑하고 `is_lifeart_admin()`을 신설해 봉쇄.
- 결제 위조 방지: 주문의 결제 확정은 **서버(Worker)의 service_role만** 기록하도록 정책 설계.

### 기능
- **소셜 회원가입/로그인** (구글·카카오, Supabase OAuth). OAuth 복귀 시 신규 계정만 LifeArt로 귀속.
- **비즈니스(기업·단체 제휴)**: 웨딩·돌잔치 / 여행·골프·산악회(+아날로그 필름 스캔) / 키오스크 제휴 / 제휴 문의.
- **표준 이용약관·개인정보처리방침** 게시 + 회원가입 시 **필수 동의** 절차.

## Stage 3 — 고객지원 · 온라인 결제 (Day 5–6)  · v0.3.x

- **고객지원**: 공지사항 · FAQ(관리자 등록분 실시간 표시) · 1:1 문의 · 견적 문의.
- **토스페이먼츠 결제 연동**: 주문 → 카드 결제 → 서버(Worker) 승인 확인 → 주문 상태·결제 기록.
  - 클라이언트는 주문 생성까지만, **결제 확정은 서버가 처리**하여 위조 차단.
- 마이페이지: 주문 내역 · 견적/제휴 문의 내역 · 회원정보 수정.

## Stage 4 — O&M 운영 관리 (Day 7–8)  · v0.4.x

온라인몰답게 **거래 중심 관리자 콘솔**을 구축했습니다. (모두 테넌트 스코프 RPC 경유)
- **매출 현황 대시보드**: 총매출·이달매출·결제완료/전체 주문·회원 수 + 최근 주문.
- **주문 관리**: 주문자(회원)·상품·결제상태(토스)·배송상태 통합 조회 및 배송상태 변경.
- **회원 관리**: 회원별 총 구매액·주문 건수·최근주문 + 주문 이력 드릴다운, 역할 변경.
- **문의/공지/FAQ/보도자료** 등록·답변, **첫 화면 히어로 이미지** 교체.
- 브라우저가 직접 못 읽는 `auth.users`는 `SECURITY DEFINER` RPC로 안전 노출.

- **Dev 툴킷 & 테스트 데이터**: 테스트 계정 원클릭 로그인, 관리자 콘솔 검증용 데모 주문/결제 데이터.
