# LifeArt 홈페이지 구축 개발 일지

> 고객사: LifeArt (라이프아트, 대표 문영식)
> 벤치마킹: asukabook.jp (일본 사진작가 대상 포토북 B2B 플랫폼)
> 스택: 정적 HTML/CSS/JS + Cloudflare Tunnel + Synology NAS + Supabase(멀티테넌트) + Cloudflare Workers(토스 결제)
> 배포: `deploy.ps1` — test-lifeart(고객사 공개용) / production(www.lifeart.ai.kr) / pre-test-lifeart(비공개 검수용)
> git 태그: `lifeart-day2` ~ `lifeart-day11` (일차별 스냅샷, `-Day N`으로 단계적 배포)

---

## 1차 — 기획 및 설계
- 정보구조(사이트맵) 확정 — 아스카북 벤치마킹, 6개 메인 메뉴 약 30페이지
- 디자인 시스템 수립 — 컬러 토큰(charcoal/gold/warm-white), 타이포, 공통 컴포넌트
- DB 스키마 설계(Supabase), Cloudflare 터널 + NAS 인프라 셋업
- 산출물: 기획·설계 문서 (코드 커밋 없음)

## 2차 — 메인페이지 + 브랜드 소개
- 메인 히어로 + 실제 협력사 로고 배너(SK·삼성·현대·두산·Google 등) + 4대 상품 카드
- LifeArt 소개 4종: 이야기 / CEO 인사말 / 오시는 길 / 보도자료
- H:\lifeart 실자료(25년 경력, 한화오션 VIP앨범, 캐논 협력사, 특허 6건) 반영

## 3차 — 상품 허브 + 삽입식 기념앨범
- /products 허브, 삽입식 기념앨범 상세(마트 방식·제작 프로세스)
- 공통 헤더/푸터 파트셜 분리(fetch 주입), Supabase 클라이언트 설정

## 4차 — VIP 앨범 + 액자
- VIP 앨범(Tier A/B/C, 한화오션 사례), 액자 상세
- 액자 실제 단가표 44종(슬림크리스탈·티크목·삼각소) 반영

## 5차 — How-to · Business · Support
- 제작과정 가이드, 비즈니스(웨딩/여행골프/키오스크 제휴)
- 고객지원(공지/FAQ/1:1문의/견적문의) + 문의 폼 3종 → Supabase 저장

## 6차 — 회원 시스템 + 마이페이지
- Supabase Auth 이메일/비밀번호 가입·로그인
- 마이페이지 4탭(주문내역/견적함/제휴현황/회원정보)

## 7차 — 상품 DB 연동 + 주문 흐름
- 액자 44종 실제 단가 DB 시딩, 로그인 후 실제 주문(pending) 생성

## 8차 — 토스페이먼츠 연동
- 결제 검증 Cloudflare Worker(lifeart-toss-verify) 실제 배포
- 체크아웃 → 결제 → 성공/실패, 주문-결제 상태 관리 (결제 확정은 service_role Worker가 처리 — 위조 차단)

## 9차 — 관리자 페이지
- 주문 관리 + 문의 관리 (상태 변경)

## 10차 — QA 점검
- 전 페이지 링크 정합성, wip(개발 예정) 태그 점검, 배포 제외 처리

## 11차 — O&M 고도화 + 멀티테넌트 정비 + 인프라 (계획 외 확장)
- **공유 Supabase 전면 멀티테넌트 정비**: 신규가입 버그 수정, tenant_id + RLS로 허브·경매·이메일·자산관리와 격리, 관리자 승격 차단, 고객사 인수인계용 독립 스키마 + 테넌트 데이터 export
- **O&M 관리자 콘솔**: 공지 CRUD, FAQ CRUD, 문의 통합관리(1:1·제휴 답변, 견적 목록)
- **dev 툴킷**(?dev=123) 테스트 계정 원클릭 로그인
- 관리자 헤더 링크 + 회원가입/로그아웃 헤더 노출(6차 UX 누락 수정)
- 배포 버전 자동증가 정책 + 캐시버스팅
- **테스트**: 결제 E2E(Playwright) + 전 기능 스모크 스위트(21 pass)

## 알려진 잔여 항목 (완료 조건)
- **토스 실제 가결제 E2E**: 클라이언트·시크릿 키 + lifeart 도메인 등록 완료. 카드 결제 경로로 완주 확인. (간편결제는 토스 테스트모드 특성상 미동작 — 정상)
- **실 운영 전환 시**: LifeArt 사업자 명의 토스 상점(정산 계좌 분리), 라이브 키 교체
- **캐시 정책**: 현재 버전 쿼리 캐시버스팅 사용. 허브식 퍼지로 통일하려면 토큰 존 확장 필요 (추후 결정)

## 비고
- 11차는 원래 10일 계획에 없던 추가 고도화(멀티테넌시·O&M·결제 테스트·인프라)로, 실제 개발 범위가 견적을 초과함 — 정산·향후 협의 근거로 기록.
