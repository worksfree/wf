### 2. 프로세스 폭주 문제 분석 및 해결 시도 ⚠️

#### 문제 발생
- **증상**: `bom2excel.exe` 실행 시 프로세스가 계속 증가 (15개 → 무한 증가)
- **영향**: CPU 사용량 100% 도달, 시스템 먹통

#### 원인 분석
1. **cpuinfo 라이브러리**:
   - `wf_hwinfo.py`에서 `cpuinfo.get_cpu_info()` 사용
   - 내부적으로 multiprocessing 사용
   
2. **PyInstaller 환경**:
   - frozen 실행 파일에서 multiprocessing이 재귀적으로 자식 프로세스 생성
   - `freeze_support()` 없이 실행 시 무한 스폰

#### 해결 방안 구현
**1) multiprocessing.freeze_support() 추가**
```python
# ui_main.py 최상단
import multiprocessing
multiprocessing.freeze_support()
```

**2) Windows Named Mutex 단일 인스턴스 가드**
```python
def _acquire_single_instance(mutex_name="Global\\WF_BOM2EXCEL"):
    """시스템 전역 뮤텍스로 단일 인스턴스 보장"""
    handle = kernel32.CreateMutexW(None, False, mutex_name)
    existed = kernel32.GetLastError() == ERROR_ALREADY_EXISTS
    if existed:
        return False, None
    return True, handle
```

### 4. COM 초기화 이슈 분석 및 문서화 ✅

#### 문제 분석
**질문**: 왜 BOM2Excel에서만 `sys.coinit_flags = 2`가 필요한가?

#### 원인 규명
1. **BOM2Excel 특수성**:
   - `pywinauto` 라이브러리 사용 (SolidWorks 자동화)
   - `pywinauto`는 내부적으로 COM(Component Object Model) 사용

2. **충돌 메커니즘**:
   ```
   pywinauto 임포트 → COM 초기화 (기본 모드)
   ↓
   tkinter.filedialog.askdirectory() 호출
   ↓
   COM 모드 불일치 → askdirectory 실패
   ```

3. **다른 앱과의 차이**:
   - 다른 앱: `pywinauto` 사용 안함 → COM 충돌 없음
   - BOM2Excel: `pywinauto` 사용 → COM 사전 초기화 필요

#### 해결책 문서화
**automation.py 주석 개선**:
```python
# COM 초기화 (pywinauto와 tkinter.filedialog의 COM 충돌 방지)
# pywinauto는 SolidWorks 자동화를 위해 COM을 사용하며,
# tkinter.filedialog도 Windows 파일 다이얼로그를 위해 COM 필요.
# 두 라이브러리가 같은 스레드 모드로 COM을 초기화하도록 설정.
# 2 = COINIT_APARTMENTTHREADED (단일 스레드 아파트먼트 모드)
sys.coinit_flags = 2
```

### 1. PyInstaller + multiprocessing
- **교훈**: frozen 환경에서는 반드시 `freeze_support()` 호출 필요
- **예방**: 모든 PyInstaller 빌드에 기본 템플릿으로 추가

- **교훈**: COM 사용 라이브러리는 임포트 순서와 초기화 모드가 중요
- **해결**: `sys.coinit_flags` 사전 설정 + 명확한 주석
