### 2. 배포 구조 수정 - settings.json 누락 해결 (11월 16일)
- **문제 인식**
  - 배포된 앱에서 `settings.json` 파일이 누락됨
  - `credit_history.json`, `credit_policy.json`은 자동 생성되지만 `settings.json`은 수동 번들링 필요

- **근본 원인**
  - spec 파일이 config를 `config/` 디렉토리에 번들링
  - 앱은 `.wf_rpa/{app_name}/` 경로에서 설정 파일 읽기
  - 경로 불일치로 인한 파일 누락

- **해결 방법**
  - 4개 앱 모두의 spec 파일 수정
  - `settings.json`을 올바른 `.wf_rpa/{app_name}/` 경로에 번들링
  ```python
  # 추가된 코드 (모든 spec 파일)
  settings_src = config_dir / app_name / "settings.json"
  if settings_src.exists():
      datas.append((str(settings_src), f".wf_rpa/{app_name}"))
  ```

### 3. 버전 관리 시스템 일원화 (11월 17일)
- **이전 상태**
  - 버전 정보가 3곳에 분산: `version.json`, `settings.json`, `credit_policy.json`
  - `full_version`, `display_version`, `version` 등 중복된 키
  - 불일치 가능성 상존

- **구현된 단일 소스 시스템**
  - **유일한 버전 소스**: `settings.json`의 `app_config.full_version`
  - **v 접두사**: "v0.7.4.2" 형식으로 통일
  - **동적 파싱**: `display_version`은 `full_version`에서 앞 2자리 추출 (v0.7.4.2 → v0.7)
  - **파일 정리**: 
    - `version.json` 삭제 (bom2excel에서 발견되어 제거)
    - `credit_policy.json`에서 `full_version` 필드 제거
    - `wf_settings_common.py`에서 `full_version` 쓰기 로직 제거

- **코드 변경**
  ```python
  # 4개 앱 모두 동일한 패턴 적용
  def _load_version_info():
      """
      ⚠️ 버전 정보 단일 소스: settings.json의 app_config.full_version만 사용
      - version.json 사용하지 않음 (제거됨)
      - credit_policy.json의 full_version 사용하지 않음 (제거됨)
      """
      # settings.json에서 full_version 읽기
      full_version = app_config.get('full_version', 'v0.7.0.0')
      
      # v 접두사 보장
      if not full_version.startswith('v'):
          full_version = 'v' + full_version
      
      # display_version은 앞 2자리만
      parts = full_version.lstrip('v').split('.')
      display_version = 'v' + '.'.join(parts[:2])
      
      return full_version, display_version
  ```
