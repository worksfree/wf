#### 1. CPU 대기 시간 최적화
**문제 인식:**
- 파일 처리 속도가 평균 1분 → 2분으로 2배 느려진 현상 발견
- `wait_cpu_usage_lower()` 함수가 파일 크기 기반 `wait_time`(120초)을 timeout으로 사용
- 3곳에서 호출되어 최악의 경우 360초 대기 발생

**해결 방안:**
```python
# 이전: 파일 크기 기반 동적 timeout
app.wait_cpu_usage_lower(threshold=40, timeout=wait_time)  # 120초

# 변경 후: 고정 timeout으로 최적화
# 1. 파일 로딩 후 (가장 중요)
app.wait_cpu_usage_lower(threshold=40, timeout=60)  # 60초

# 2. BOM 우클릭 전 (짧은 안정화)
app.wait_cpu_usage_lower(threshold=50, timeout=20)  # 20초

# 3. 저장 다이얼로그 전 (제거 - 불필요)
# app.wait_cpu_usage_lower() 제거
```

**효과:**
- CPU 대기 시간: 최대 360초 → 80초 (280초 절약)
- 파일당 예상 처리 시간: 2분 → 1분 이하로 복원
- CPU가 안정적인 경우 더 빠른 처리 가능

#### 1. 대기 시간 로직 단일화
**배경:**
- 기존: `ui_wait`, `file_save_wait`, `save_wait` 3종류 변수 사용
- 복잡도 증가 및 유지보수 어려움

**변경 사항:**
```python
# 이전: 이중 대기 시간 계산
def _compute_waits(self, file_size_bytes: int):
    ui_wait = base_wait_time + floor(file_size_mb/10) * seconds_per_10mb
    ui_wait = max(120, ui_wait)  # 최소 120초
    file_save_wait = ui_wait * multiplier  # 2배
    return ui_wait, file_save_wait

# 변경 후: 단일 대기 시간 계산
def _compute_wait(self, file_size_bytes: int) -> int:
    wait_time = base_wait_time + floor(file_size_mb/10) * seconds_per_10mb
    return wait_time
```

**계산 공식:**
```
wait_time = base_wait_time + (multiplier × seconds_per_10mb)
multiplier = floor(file_size_mb / 10)

예시:
- 9MB:  120 + (0 × 60) = 120초
- 29MB: 120 + (2 × 60) = 240초
- 91MB: 120 + (9 × 60) = 660초
```

**적용 범위:**
- UI 컨트롤 대기
- CPU 안정화 대기 (당시 - 이후 고정값으로 변경)
- 파일 저장/잠금 해제 대기

## 2025-10-25 (목요일)

### 🎯 주요 작업: SolidWorks 연결 실패 처리 및 Fatal Error 메커니즘

#### 1. Win32 백엔드 연결 문제 해결
**문제:**
- Win32 백엔드로 변경 후 SolidWorks 시작하지만 연결 실패
- 에러: "There are 2 elements that match the criteria"
- 연결 실패 후에도 계속 파일 처리 시도하여 연속 오류 발생

**원인 분석:**
- SolidWorks 실행 후 창이 준비되기 전에 연결 시도
- 여러 윈도우 감지 시 첫 번째 윈도우만 선택하여 충돌

**해결 방안:**
```python
def _safe_solidworks_restart(self):
    # 핸들 기반 연결 대기 루프 추가
    start_ts = time.time()
    connected = False
    while time.time() - start_ts < self.wait_time:
        try:
            wins = findwindows.find_windows(title_re=self.config.application_title)
            if wins:
                # 여러 윈도우 감지 시 마지막 윈도우 선택 (최신)
                target_handle = wins[-1] if len(wins) > 1 else wins[0]
                if len(wins) > 1:
                    self.logger.warning(f'여러 개의 SolidWorks 윈도우 감지됨')
                self.Solidworks_App = Application(backend=self.pywinauto_backend).connect(handle=target_handle)
                connected = True
                break
        except Exception:
            pass
        time.sleep(0.5)
```

#### 2. Fatal Error 메일 메커니즘 구현
**요구사항:**
- SolidWorks 시작/연결 실패 시 즉시 전체 작업 중단
- 단일 에러 메일만 발송 (중복 방지)
- 이후 파일 처리 시도 중단

**구현 내용:**
```python
class BomAutomation:
    def __init__(self):
        self.abort_all = False          # 전역 중단 플래그
        self.fatal_email_sent = False   # 중복 메일 방지
    
    def _send_fatal_email(self, title, content):
        """치명적 오류 메일 발송 (로그 첨부)"""
        if self.fatal_email_sent:
            return
        # 메일 발송 로직
        self.fatal_email_sent = True
    
    def _sanity_check_solidworks(self):
        """사전 점검: 파일 처리 전 SolidWorks 연결 확인"""
        ok = self._safe_solidworks_restart()
        if not ok:
            self._send_fatal_email('[B2E] Fatal - SolidWorks sanity check failed', ...)
            self.abort_all = True
            return False
        return True
```

**적용 위치:**
1. `open_sldprt_files()` 시작 시 sanity check 실행
2. `_process_files_batch()` 내 재시작 실패 시 fatal email 발송
3. 파일 처리 루프에서 `abort_all` 체크하여 조기 종료
