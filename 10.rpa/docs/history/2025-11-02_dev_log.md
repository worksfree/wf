# 개발 일지 (2025-10-27 ~ 2025-11-02)

## 개요
이번 주에는 BOM2Excel 자동화의 안정성과 UI 사용성을 높이기 위한 개선에 집중했습니다. 특히 파일 열기/저장 모달이 잔존하여 다음 파일 처리까지 연쇄 실패하는 문제를 해결했고, UI 스피너/진행률, 설정창 레이아웃, 관리자 모드 진입 기능을 보완했습니다.

## 변경 사항 요약
- 모달/대화상자 잔존으로 인한 연쇄 실패 방지 워치독 추가 및 통합
- 파일 처리 스레딩 구조 재검토: 메인 스레드 UI 업데이트 보장, 스피너 응답성 개선
- 스피너 동작 타이밍 보정(파일 처리 중에만 동작)
- 설정창 레이아웃 재배치(왼쪽: 최상위 고정/재시작 여부, 오른쪽: 속도/재시작 카운트)
- 크레딧 라벨 클릭 시 관리자 인증/관리자 모드 진입(창 높이 증가) 기능 추가
- 동적 대기시간 계산(파일 크기 기반)과 연속 타임아웃 안전 재시작 보강
- 메모리 모니터링 기반 선제적 재시작 도입(옵션)
- 최종 실패/성공 리포트 이메일 로직 정리

## 상세 변경 내역
### 1) 모달/대화상자 워치독
- 파일 열기/저장/오류 모달이 남아있을 때 다음 파일 처리에 영향을 주지 않도록, 안전 정리 유틸을 추가했습니다.
  - `BomAutomation._dismiss_common_dialogs(app=None, attempts=2)`
    - 메인 SolidWorks 창은 절대 닫지 않도록 핸들 기준으로 제외.
    - 타이틀 키워드(열기/Open, 저장/Save As, 오류/경고/Error/Warning/확인) + 대화상자 클래스(#32770/Dialog) 둘 다 만족하는 창만 대상.
    - 닫기 순서: 버튼 클릭(취소/아니오/확인/닫기) → (파일 대화상자만) `close()` → ESC.
    - Alt+F4 금지 (본체 종료 위험 제거).
  - `BomAutomation._cleanup_ui_state(app=None)`
    - 위 유틸 실행 후 포커스 복원 + ESC 2회.
- 통합 지점
  - 각 파일 처리 루프의 시작마다 선제 호출(잔존 모달 제거).
  - `save_bom2excel` 시작 직전(Ctrl+O 전)과 예외 처리부(오류 시)에서도 호출.

### 2) 스피너/진행률/스레딩
- 파일 처리 시작 콜백(`file_processing_start_callback`)에서 스피너 시작, 진행률 업데이트에서 스톱하도록 보정.
- 긴 작업은 백그라운드 스레드로 수행, UI 업데이트는 `after(0, ...)`로 메인 스레드에서 실행.
- 진행률 텍스트/바 업데이트 시 UI 멈춤 현상 완화.

### 3) 설정창 레이아웃
- 요구사항에 따라 다음으로 배치 수정:
  - 왼쪽: “최상위 고정”, “재시작 여부”
  - 오른쪽: “속도”, “재시작 카운트”
- Grid 정렬/여백 조정으로 좌측 정렬 가독성 개선.

### 4) 관리자 모드
- 크레딧 라벨 클릭 → 관리자 비밀번호 입력 → 성공 시 관리자 모드 전환(현재는 메인 창 높이 증가).
- 추후 관리자 전용 컨트롤 노출 영역으로 확장 가능.

### 5) 안정성/회복력
- 파일 크기 기반 대기 시간 계산(`_compute_wait`)으로 대기 일원화.
- 연속 타임아웃 누적 시 안전 재시작(`_increment_consec_and_maybe_restart`, `_safe_solidworks_restart`).
- 메모리 임계치 하회 시 선제적 재시작(`_check_memory_and_maybe_restart`)으로 Out-of-Memory 리스크 저감.
- 시작 전 사전 점검(`_sanity_check_solidworks`)으로 연결/시작 실패를 일찍 감지.

### 6) 리포트/알림
- 1차/2차 시도 결과 및 최종 실패 목록을 이메일로 통지.
- 크레딧 부족 중단 시 별도 제목/내용으로 알림.
